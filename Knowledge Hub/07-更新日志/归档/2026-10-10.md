## 升级点击模型消失修复（ShowModelAsync 同角短路）

**现象**：一点升级（角色/武器都一样）就报 `Addressable 资源加载失败：CH0221(GameObject)`，升级数据已落但当前角色模型消失，要切走再切回才回来。

**根因链**（两层叠加，病灶在面板层）：
1. **双广播**：升级结算写两次仓库（`SetLevel` + `SetExp`，CharacterProgressionManager.cs:250-251 角色 / :449-455 武器与突破），每次各广播 `CharacterDataUpdated`；`OnCharacterDataUpdated` 是 fire-and-forget `_ = SelectCharacterAsync(model.UnitId)`，无去重 → 同 unitId 两条并发刷新链。喂养重构前直喂路径只写一次，是重构引入的形态；突破同型。
2. **租约竞态**：两条链同地址进 `ShowModelAsync` → AddressableManager `GetOrLoadEntryAsync` 去重并发、共享同一 entry；输家链从 await 醒来时发现令牌已失效 → `lease.Dispose()`；若这步落在「赢家 await 完成后、CreateLease 前」的窗口，引用计数被砸到 0 → entry 释放句柄并从 resources 摘除 → 赢家拿到已死 entry → `IsLoaded=false` → 包装层静默抛「资源加载失败」（操作本身成功，无 Addressables 异常日志，故难查）。

**架构结论（用户追问「刷新数据为什么会涉及 Addressables 加载」）**：刷新确实不该加载模型——模型内容与数值无关。修复不做 Core 改动，在面板层把「升级/突破回流刷新」降级为纯数据刷新：`ShowModelAsync` 顶部同角短路（`loadedModelId == unitId` 直接 return），`ReleaseModel()` 后立即置 `loadedModelId = unitId` 作**在途占位**（加载完成前同角再入也短路，双广播只剩一路加载）；catch 与锚点缺失路径清占位（下次可重试）；令牌失效路径不清（占位已归新链）。原挂载成功后的 `loadedModelId = unitId` 变冗余已删。顺带效果：升级不再模型重载闪烁、不再重播展示时间线。

**教训**：
- fire-and-forget 事件回流的刷新动作要先想「这条广播值得重做什么」——数据广播的默认动作应是刷新数据展示，不该借用「切角」的全量通道（含模型加载）。
- 共享 entry 去重 + 租约计数模式下，「await 返回后置租约」之间永远有窗口；调用方侧消除并发重复请求比 Core 侧加兜底更对症。Core 侧 `GetOrLoadEntryAsync` 重试兜底作为可选加固另议（需用户同意才动框架）。

**验证**：重编译零错（dll mtime 刷新 + console 无新 error，本改动无新字面量/类型，二进制 grep 无新增判据）。待 Play 实测：升级/突破后模型不消失不闪烁、数据与文本正常刷新；切角/关板/加载失败重试语义不变。

## NoticePanel 单条通知不消失（用户报「hide 没设置为 true」）

- **病灶在 Control，不在控制器**：盘上复核 `NoticePanel.controller` 本就齐——`Hide` bool 参数、`Hide==true`→NoticeHide 转场（HasExitTime=0）都在；代码里 `SetBool(Hide, true)` 是**不可达死代码**：`OnUpdate` 开头 `if (pending.Count == 0) return;` 把整个计时挡死——单条消息 `ShowNext` 出列后队列变空 → 后续每帧早退 → `remain` 永不递减 → 到点分支（含排空置 Hide）永远走不到。**多条连发时队列非空、计时照走，所以测双条正常、单条必现**——典型的"只测了快乐路径"漏网。
- **修正**：计时只看 `occupied`，与队列是否为空解耦——`occupied` → 计时 → 到点无货置 Hide / 有货同帧顶上；`!occupied` 且队列有货才 ShowNext。行为面不变（连续供弹不回落不重触发），只是单条终于会退场了。
- 编译零错（dll 刷新 + console 无新 error）。重测点：单条通知 popupInterval 秒后收回；连发逐条轮换最后一条收回；发送间隔内新消息顶上不重触发。

### 补充：机制改版为单条消息模型（同日，用户拍板）

上面修完 bug 后用户直接改拍板：**废除缓冲队列，换单条消息模型**——Submit 立即覆盖旧文案 + `SetTrigger(NoticeTrigger)` 重触发 + 计时复位（连发即刷掉上一条）；无新消息则静默 popupInterval 秒后 `SetBool(Hide, true)` 回落。队列/ShowNext/`using System.Collections.Generic` 全删，代码反而更短。
- **控制器侧零改动**，盘上复核拓扑正合适：**Any State→入场**（NoticeTrigger 触发条件，`m_CanTransitionToSelf: 1`）——在入场态里再触发也能重入重播动画，这是"连发刷掉上一条且重播入场"成立的前提；入场→NoticeHide（Hide==true）；NoticeHide 为默认态无出边。
- 行为对照旧版：旧版连发"顶上不重触发"（文本换、动画不重播）；新版每条都重播入场动画（0.25s crossfade）。
- 重编译零错。重测点：单条 2s 回落；连发每条重播入场、文本即刷；停留期内新消息计时复位；**升级材料不足等 Core 拒绝提示（NoticeRequested 事件）走同一 Submit，行为同步生效**。

## Home 钱币栏与培养面板数据不一致（用户报「两套数据来源就跟不一样一样」）

**表象**：Home 栏钱币全 000（点 + 后变 10000），培养面板 GearBar 正常显示 55000/30000；Home 的 + 会"自己加自己的"。

**诊断路径**：先猜"成本格没订阅 BagUpdated"被用户证伪（两根栏本身数值就不同源）→ Play 模式注入反射探针，读活跃实例真实持有的 id 字段，一炮定位。

**根因（陈旧原生资产缓存）**：
- id string 化迁移当天的上午窗口，脚本默认值是 `"2"/"1"`；HomePanel 在该窗口被载入编辑器内存，缺失字段按**当时**默认值烤进原生资产缓存。
- 下午默认值重映射 `Currency_*`，但 **HomePanel.prefab 磁盘从未保存过**（mtime 还在 10-07，YAML 无 id 字段）→ 文件没变 → Unity 永不重新反序列化 → 内存里 "2"/"1" 活到现在。
- 运行中 HomePanel 读 `"2"`（初始 0 → 全 000）/`"1"`（永远 0）；`+` 按钮 `AddItem("2", 10000)` 写进背包幽灵条目——"两套数据"的实体。培养面板 GearBar 的 id 是 CultivatePanel.prefab 显式序列化的 Currency_*，所以正常。
- 探针关键证据：活跃实例（DontDestroyOnLoad）`statusMoneyItemId="2"`，且 FindObjectsOfTypeAll 找到的 scene="" 实例（= 内存里的预制体资产本体）同样持有 "2"——**盘上干净、内存陈旧**的铁证。

**修复（零代码改动，磁盘零写入）**：
1. `AssetDatabase.ImportAsset(path, ForceUpdate)` 强制重导入 4 个面板预制体（HomePanel + CharacterListPanel/CombatSelectPanel/FormationPanel 的 GearBar 同型隐患）→ 内存资产按磁盘重建，缺失字段落到当前脚本默认 Currency_*；重导入后回读 SerializedObject 验证四板全部 Currency_CreditPoint/Currency_StarlightStone。
2. 幽灵条目清理：反射调 `InventoryManager.TryRemove("2", 实有量 10000)` → 归零删条目并即时存档；回读 GetCount("2")=0，真身 55000/30000 不动。

**教训（已入库记忆）**：改脚本序列化字段默认值 ≠ 改资产——磁盘未变的预制体在编辑器内存里永远保留旧默认值，静态看盘查不出，只有读活实例字段才暴露；迁移默认值后要对受影响预制体强制重导入（或重启编辑器）并回读验证。
