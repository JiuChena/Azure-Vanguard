# 2026-10-07

## Azure Vanguard — 池化 Item 108 倍放大修复（ObjectsPool 取出路径）

- **现象**：用户实测养成面板左列角色 Item 被放大 108 倍（预制体出厂干净，全文件无异常 scale 值）。
- **根因**：`ObjectsPool.Get` 池空时 `Instantiate(模板)` 在**无父状态**克隆——Unity 会把源对象的**局部**变换值落成实例的**世界**变换；随后 `SetParent(parent, true)` 保世界尺度挂回，局部尺度 = 模板局部 / 挂点链 lossyScale P。养成面板挂点链 P ≈ 1/108 ≈ 0.00926，新实例正好放大 108 倍。池里有旧实例的复用路径无此问题（世界尺度往返抵消），只有"池空首取"的新实例中招。
- **修复（按用户拍板：挂载后设 scale = 1,1,1）**：两个业务取用点（`CharacterListPanel.RefreshList` / `CultivatePanel.RefreshBar`）在 `ObjectsPool.Get` 之后 `transform.localScale = Vector3.one`。GridLayout 不管理 scale，位置会自校正，尺度必须显式归一。
- **未动框架**：治本方案是 `ObjectsPool.InstantiateAndDeliver` 改 `SetParent(parent, false)`，但那是 Core.Gear 高风险改动（影响 VFX 等全部消费方），待用户拍板再说。
- **编译**：一次泵过，dll 刷新 + groundTruth `compilationFailed:false/consoleErrors:0`。

## Azure Vanguard — 位置归零口径修正 + 入池诊断 + HomePanel 菜单栏 NRE 修复

- **位置归零改 localPosition（用户拍板）**：上一版归零用的是 `anchoredPosition`（只覆盖 X/Y，z 轴不动）。用户指出应为 local 空间三轴归零：`go.transform.localPosition = Vector3.zero`。用户自己先在 `CharacterListPanel.RefreshList` 手改落地，本会话同步到 `CultivatePanel.RefreshBar`，两处注释统一为"localPosition 三轴归零含 z 轴"。GridLayout 排布接管 anchoredPosition，localPosition.z 归零不影响排布、只清掉克隆误植的 z 偏移。
- **"旧 Item 没入池"结论（同帧瞬态）**：三轮代码追踪确认 `ObjectsPool` Put/Get 机制无缺——`RefreshList` 是"全部入池 → 立即按新顺序全部取出"的**同帧**操作，池静止时永远是空的，肉眼看池节点像"没入池"，实际旧 Item 就是复用的那批实例。为此在 `RefreshList` 末尾加诊断日志：`池化刷新：入池 {pooledCount}，重建 {count} 项`——**入池数 ≥ 重建数即全程复用零新建**（首开时入池 0/重建 N 属正常新建；排序切换时应看到入池数等于上一轮数量）。
- **HomePanel NRE（HomePanel.cs:54）**：报错栈 `EventInit → menuBar.cultivatedButton.onClick`。预制体排查：`HomePanel_MenuBar` 组件上**六个引用全部 fileID: 0**（studentsButton/cultivatedButton/storeButton/gachaButton/taskButton/timeText）——菜单栏节点被重搭（Button 变为各入口 Store/Students/Gacha/Task/Cultivate 的二级子节点）后引用没接回；同预制体其他 View 分区全部完好。修复 `AgentScripts/RepairHomeMenuBar.cs`：LoadPrefabContents → 按路径 `Store/Button` 等五路接线 → 任一未命中不落盘 → 落盘回读 **students/cultivated/store/gacha/task 全 True**，YAML 复核五个字段均指向真实组件。`timeText` 无对应节点维持留空（代码侧本就是 TODO）。

## Azure Vanguard — 交互音效二轮：列表项补接线 + 下拉"声音偏大"根因（2026-10-07 用户反馈）
