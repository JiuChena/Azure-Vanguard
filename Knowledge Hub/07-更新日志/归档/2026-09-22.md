## Azure Vanguard — Preload 面板：开场动画播完再开始加载

用户反馈 Preload 面板有打开动画，需要动画播完再开始场景加载切换。

### 问题

`PanelManager.OpenPanel` 的 callback 在 `DisplayPanel()` 之后**同帧立即**触发（PanelManager.cs），而开场动画（Animator 默认状态播 Preload.anim，动画驱动 `dissolveAmount`，`OnUpdate` 写入材质）刚开始播——加载与动画并行。

### 修法（不动 Core.Gear）

- `PreloadPanel`：覆写 `DisplayPanel()` 重置标记；`OnUpdate` 用 `GetCurrentAnimatorStateInfo(0)` 检测——首次有效状态捕获哈希（默认状态=开场动画），**离开该状态（自动过渡）或 normalizedTime ≥ 1** 即算播完，触发一次性回调；新增 `AddDisplayFinishedListener(UnityAction)`（已播完则立即执行，防订阅竞态）。无 Animator/无控制器直接放行（兜底=旧行为）。
- `Preloader`：把 `LoadSceneManager.LoadSceneAsync(Home)` 从 OpenPanel 回调挪进 `AddDisplayFinishedListener`。

### 通道结论补充（图集设置）

importer 的 `SerializedObject` + `SaveAndReimport()` **能持久化**设置（packables 的 `Add()` 依然不落盘，见调试笔记）；图集设置序列化在 `.meta` 的 `SpriteAtlasImporter` 块，不在资产 YAML 里。

## Azure Vanguard — AddressableManager 标签加载（三类 API）

用户确认加多标签版本（并集 + 交集）与"地址 + 标签"版本，沿用现有 Lease 模型返回 `List<ResourceLease<T>>`。详见 [[modules/azure-vanguard]] 的"资源加载"节。

### 设计

- 三类 API 对齐用户梳理的加载语义：①资源地址（原有）；②按标签批量（新增并集 `AcquireAssetsByLabelsAsync` / 交集 `AcquireAssetsByLabelsIntersectAsync`）；③地址+标签（新增 `AcquireAssetWithLabelsAsync`，地址必须带全部指定标签，空标签退化按地址）。
- 批量实现：`LoadResourceLocationsAsync` 解析命中地址（PrimaryKeys，临时 Handle 即刻释放）→ 两遍式（先全部加载、后统一建 Lease），任一失败不产生半批引用；与单 key 共享缓存条目。
- scope 不内部创建，调用方自备（面板传自己的 scope，常驻走 `ResourceScope.Persistent`）。

### 踩坑（Addressables 1.22.3）

- `MergeMode` 枚举交集成员是 **`Intersection`**，写 `Intersect` 直接 CS0117 ×2。
- `LoadResourceLocationsAsync(IList<object>, MergeMode, Type)` 标了 `[Obsolete]`，而 `List<object>` 会精确匹配到它——必须 `(IEnumerable)keys` 才绑到现行 `IEnumerable` 重载，否则 CS0612。

### 工作流坑：CLI 下编辑器不自动重编译

`AssetDatabase.Refresh()` 在 run_script 执行期间只排队不编译（编译要等脚本返回后的编辑器循环），而 CLI 场景下编辑器循环又迟迟不触发，导致 CompileCheck 反复读旧结果（failed=True 是上一轮的残留）。解法：单独跑 `CompilationPipeline.RequestScriptCompilation()` 强制编译，再 CompileCheck 拿结果（脚本 `AgentScripts/Recompile.cs`）。editor_status 在编译窗口期也抓不到 `compiling: true`，别拿它判断"没编译"。

## Azure Vanguard — 简化版 GTS + 流动 Shader

用户要两个 shader：①简化版 GTS——仅 BaseColor/NormalMap、最省计算的场景卡通渲染、提供描边变体；②时间偏移流动 shader——xy 速度独立控制、自发光、透明通道。中途补充：简化版需兼容 URP Lit，换 shader 贴图数据不丢。详见 [[modules/azure-vanguard]] 的"Shader"节。

- **GTSLite.shader**（GTS/General Toony Shader Lite，Toony/GTS/）：属性名直接沿用 URP Lit（`_BaseMap/_BaseColor/_BumpMap/_BumpScale/_Cull`）——Unity 换 shader 按同名属性迁移，Lit 材质直接切换不丢贴图。渲染只留：法线扰动 → NL 两阶明暗（smoothstep 分界 + 柔化）→ 阴影色/原色插值 × 主光色；实时阴影衰减**并入色阶**（被投影像素直接落阴影档）；SH 环境光兜底。描边 = 反向壳 Pass（无 LightMode 标签走 SRPDefaultUnlit，Cull Front 沿世界法线外推固定宽度），`_OUTLINE_ON` 关闭时顶点塌缩不产生像素。ShadowCaster/DepthOnly 用 UsePass 借 URP Lit。
- **FlowSurface.shader**（Effect/Flow Surface）：`uv + float2(_FlowSpeedX, _FlowSpeedY) × _Time.y`，xy 速度独立可负；同一次采样同时喂底色与自发光（HDR 色 × 强度，不经过主色调制）；透明队列 SrcAlpha/OneMinusSrcAlpha、ZWrite Off，无缝流动依赖贴图 Repeat。
- 校验：新脚本 `AgentScripts/ShaderCheck.cs`（Refresh 同步导入 → `ShaderUtil.ShaderHasError`），两个 shader 均 hasError=False / supported=True。
- 坑：SRP Batcher 要求**同一 shader 所有 Pass 的 UnityPerMaterial 布局一致**——GTSLite 两 Pass 共用同一份全量 CBUFFER；现有 GTS 全功能版两 Pass CBUFFER 不同（描边 Pass 只声明描边属性），按规则不可批处理（渲染正常，只是合批失效），历史遗留未动。
