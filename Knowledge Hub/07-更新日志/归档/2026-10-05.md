## Azure Vanguard — CameraManager（相机管理器）交付

- **需求**：相机管理器——可序列化字典（枚举键→相机）、单例、Awake 自动 DontDestroyOnLoad、动态注册/注销、访问 API。
- **交付**：`Assets/Scripts/CSharp/Core/Gear/Common/CameraManager.cs` + `CameraType.cs`（namespace `Core.Gear`）。
- **关键设计**：
	1. **没复用 `SerializableDictionary`**：注销要 Remove、导入要枚举，框架类都没有；给框架类加接口属高风险操作需另征同意，改按用户"双列表模拟"授权在 Manager 内自持双列表。
	2. **序列化数据运行时零回写**：Inspector 双列表仅作 Awake 导入种子，注册/注销全走私有运行时 Dictionary——编辑器 Play 模式下改序列化字段会持久化进场景/Prefab，这是不回写的根因。
	3. **Unity-null 自愈**：TryGet 命中键但相机已销毁（随场景卸载）→ 清脏条目 + 告警，按未注册处理；Get/ContainsKey 同口径，杜绝把 destroyed 相机发给调用方。
- **验证**：Recompile 后 `Assembly-CSharp.dll` mtime 刷新（19:41:12）、Editor.log 零 `error CS`（枚举若有重名必报 CS0101，零错误即无冲突）。
- **坑（时间线）**：git 快照里出现过 `Bissness/CameraManager/` 目录与"早于写入时间"的文件 mtime，一度疑似覆盖用户文件——实为会话两步之间隔了约 47 分钟真实时间，且该目录是用户建的空目录、已被 Unity 自动清理，无内容损失。
- **关联**：[[modules/azure-vanguard]] 相机管理节。

## Azure Vanguard — Canvas 相机挂载排查（未解之谜 + 用户侧结案）

- **现象**：Canvas.prefab YAML 明确 `m_RenderMode: 1`（ScreenSpaceCamera），但运行时/CLI 新进程 `AssetDatabase` 直读解码为 **Overlay**，PanelManager 判定分支恒走"非 SSC"不挂相机（Editor.log 可见 321/123）。地址映射唯一、无 catalog（排除旧 bundle）、无脚本改 renderMode，全部常规嫌疑排除。
- **已证伪**：枚举编码（roundtrip 实证 SSC 序列化=1，与文件一致）、Addressables 旧资产（溯源 servedGuid=目标预制体）、Play Mode 打包通道（磁盘无 bundle/catalog）、运行时改动（全项目 grep 无 renderMode 写入）。
- **未解**：同一文件、同一 Unity 版本（2022.3.55f1c1），序列化写 1、反序列化读 0——直接原因未查明（用户拍板"不管了"）。
- **结案口径（用户改定）**：PanelManager 不再判定模式，**实例化后无条件 `worldCamera = CameraManager.Get(UI)`**。Overlay 渲染路径不使用 worldCamera，强挂零副作用（渲染、射线都不用）；若将来真落在 SSC 上，相机已在位，两头通吃。
- **遗留提醒**：首次 OpenPanel 时若场景尚无 CameraManager 实例，`CameraManager.Instance` 为 null → EnsureCanvasLoaded 抛 NRE → OpenPanel 回滚面板打不开；场景需先有 CameraManager 且 UI 相机已注册。
- 诊断脚本 `AgentScripts/VerifyCanvasLoad.cs`（最终版=枚举编码 roundtrip）留存，可删。
