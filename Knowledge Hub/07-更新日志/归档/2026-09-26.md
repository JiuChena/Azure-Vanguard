## Azure Vanguard — HaloHelper 恒定距离平滑跟随器

用户需求：`HaloHelper` 脚本，LateUpdate 中参考一个 Transform 的位置、旋转跟随，跟随用 Lerp，**跟随后与目标的距离与初始距离保持一致**。

- 位置：`Bissness/Effects/HaloHelper.cs`（全局命名空间，Bissness 惯例）。
- 实现：Start 时把世界偏移与相对旋转转入**目标本地空间**记录（`initialLocalOffset` / `initialLocalRotation`）；LateUpdate 中期望位 = 目标位 + 目标旋转 × 初始本地偏移，`Vector3.Lerp` 平滑后**重新投影**回以目标为球心、初始距离为半径的球面锁死距离；旋转 `Quaternion.Lerp` 逼近 `目标旋转 × 初始相对姿态`。
- 关键设计：距离约束下两端点都在球面上，Lerp 中点会内切偏近，必须重投影（方向取 Lerp 结果、模长锁回初始距离）；目标平移时位置误差经方向项指数衰减，半径恒定不脱节。
- Lerp 系数用 `1 - e^(-速度×dt)` 帧率无关化（速度字段单位 1/秒）。
- 边界：目标为空不跟随；初始与目标重合（距离≈0）退化为普通位置 Lerp；公开 `CaptureInitialPose()` 供目标晚就位/传送后重置基准。
- 已过 dev-standards 自检（Tooltip/Header、字段 // 注释、XML summary、编译零报错）。

## Azure Vanguard — CombatReadinessPanel（战备面板）实现

用户口述规格落地，场景结构（Preload.unity 已探明）：

```
CombatReadinessPanel（根，Control，实现 IDragHandler 接收整树拖拽）
├─ CHList1 / CHList2   ← 左右两页根（CHInfoList 就挂页根上，整页 SetActive 切换）
│   └─ CH1~CH4 槽位 = { LayerInBGUI, LayerGeaterThanCH（角色展示层）, CHInfo（信息栏，兄弟节点）}
├─ CHListSwitch（OtherView：leftButton/RightButton/6 页签/编队/战斗）
└─ GearBar（状态栏）
```

- **GearBar 补字段**：`goBackHintText`（TMP_Text）+ `staminaAddButton/moneyAddButton/starLightStoneAddButton`（Button），需在 Inspector 补连线。
- **GearBarInit**（View/Generic，扩展方法式静态类）：View 不含逻辑 → 通用默认逻辑放独立初始化器。`InitDefault()` 刷新三货币文本（0 占位，TODO 指向体力系统/InventoryManager）+ 三个加号/设置/回主页默认行为（目标面板未接入，TODO log 占位）；`RegisterGoBack(action, hintText)` 唯一手动入口（RemoveAllListeners 只清运行时监听，不伤 Inspector 持久监听）。
- **页面切换 wrap**：只有两页时"左按钮在最左绕到最右"等价于两页互换，`SwitchCharacterPage()` 单方法双按钮共用；默认 ComponentInit 显示左页。
- **拖拽换位**：Control 根实现 `IBeginDragHandler/IDragHandler/IEndDragHandler`（UGUI 事件沿父链冒泡到根，无需给每个角色挂脚本）；`EventSystem.RaycastAll` 按屏幕坐标自检（不走 eventData.pointerPress，避免冒泡后拿不到子节点），从命中节点**向上**找 `tag=character`（标签可能设在槽位根或展示层，子节点不继承 tag）；**另一页隐藏不被射线命中 → 左换左、右换右天然成立**；位置互换用元组赋值 `(a.position, b.position) = (b.position, a.position)`。
- **信息栏同步**：CHInfo 与角色展示层是兄弟——标签若设在展示层，角色换位信息栏不动 → 元组互换两个 `CharacterInformation.transform.position`；标签若设在 CH 槽位根则信息栏随根走，代码里 `GetComponentInChildren<CharacterInformation>()` 判空自动跳过，两种打标签方式都兼容。
- **索引页签切换骨架**（第二轮补上）：`InitTeamToggles()` 保证单选——场景没配 ToggleGroup 时运行时补建到页签容器上并 `allowSwitchOff=false`（索引栏必须始终有一个选中），逐个 `toggle.group` 注册 + 闭包捕获局部索引防循环变量陷阱，默认 `toggles[0].isOn = true`；`SwitchTeam(index)` 记录 `currentTeamIndex`，编队配置 JSON 接入后只改这一个方法。
- **TODO 占位**：编队/战斗按钮；CloseSelf 走 `PanelManager.ClosePanel(this)`（面板未注册时被优雅忽略，纳入管理后自动生效）。
- 场景侧待用户操作：GearBar 5 个新字段连线、Control 4 个 View 分区连线、角色节点打 `character` 标签（建议 CH1~CH4 槽位根）、角色图 raycastTarget 保持开启。
- 编译两轮 Recompile→CompileCheck 均 failed=False，零错误。

## Azure Vanguard — GAS×BE×BHSM 打通（UnitConfig + Behavior 能力）

方案确认后的落地（Gizmo 划掉：BE Gizmo 只给 Timeline 看，不归 GAS 管）：

- **决策记录**：① UnitConfig 挂 GAS 组件（实体级，非行为能力附属）；② 状态经状态上下文 `PlayBehavior(key)` 间接调，不直连 executor；③ 键约定 = 叶子状态类 `public const string BehaviorKey`；④ OnEnter Play / OnExit Stop（StateBase 自带 OnExit 虚方法，无需改框架）；⑤ id 用 string；⑥ 双列表模拟字典——项目里确认**没有**现成类，新建。
- **`Core.Gear.SerializableDictionary<TKey,TValue>`**（Common，新）：双平行列表 + `NonSerialized` 懒构建查询字典；Set 运行时写列表标脏；EnsureLookup 校验两列长度不齐、重复键后者覆盖（均 Log 提示）。
- **`UnitConfig`**（GAS/Core，新 SO）：`string id` + `SerializableDictionary<string, BehaviorClip>`；CreateAssetMenu `Framework/Gameplay/Unit Config`；后续图标/阵营在此追加。
- **Behavior 能力三件套**（GAS/Behavior，新）：`BehaviorAbilitySO`（`_logBehaviorFlow` 配置）→ `BehaviorAbilityRuntime`（AbilityInit 建 `new BehaviorExecutor(owner, log)`，AbilityUpdate 常开 `Tick`，空转内部直接 return；Dispose Unregister+Stop）→ `BehaviorAbilityRuntimeData`（`Play(key)`：UnitConfig 表查 clip → executor.Play，空键/无表/键未命中分级 LogError/LWarning 并忽略；`Stop()`；Reset 空）。
- **框架侧最小改动**：`AbilityRuntimeDataType` 加 `Behavior`（auto-generated 区，纯标记无生成器）；`AbilityOwnerContext` 构造加可选 `UnitConfig` 参数 + 只读属性；`GameplayAbilitySystem` 加 `[SerializeField] UnitConfig _unitConfig` 传入上下文。
- **CH0221 测试接线**：状态上下文加 `PlayBehavior/StopBehavior`（TryGet(Behavior) 未命中 → LogWarning 跳过）；Idle/Move 状态加 `BehaviorKey` 常量（"Idle"/"Move"）+ OnEnter 播放 + OnExit 停止。
- **踩坑**：新文件漏 `using BehaviorEditor;`（BehaviorExecutor/BehaviorClip 在该命名空间）→ CS0246，补 using 后两轮 failed=False。
- **桥接闭环**：BHSM 状态 OnEnter → Context.PlayBehavior → OwnerContext.TryGet(Behavior) → UnitConfig 表 → executor.Play。**反向无需桥接**（用户纠正）：EventTrackExecutor 自带完整事件链（排序/Tick 分发/位姿解析 → `BehaviorEventExecuteSO.Execute`），GAS 不另做事件系统；玩法类事件按需写项目侧 ExecuteSO 子类（Context 已带 OwnerGameObject，GetComponent 即达 GAS），当前无需求不预建。
- 场景侧待用户：建 UnitConfig 资产（id + "Idle"/"Move" 键拖 clip）、建 BehaviorAbilitySO 资产、GAS 组件上配 UnitConfig 引用 + 行为能力进能力列表、BehaviorClip 资产从 Timeline 编译产出。
