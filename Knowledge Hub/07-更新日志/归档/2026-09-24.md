# 2026-09-24

## Azure Vanguard — Core.Expand 扩展注入启动（Transform 归零 + Button 回调栈评估）

用户定下 `Assets/Scripts/CSharp/Core/Expand` 的用途：给 Unity 现有无法修改的类做外部函数注入，**每个扩展方法单开一个脚本**。详见 [[modules/azure-vanguard]] 的"Core.Expand"节。

### 已实现

- `TransformLocalTransformReset.cs`：`transform.LocalTransformReset()`——localPosition 归零、localRotation 归位（identity）、localScale 归一（1,1,1）。
- 约定成型：namespace `Core.Expand`；所有扩展聚合在 `{类型名}Expand` 的 static partial 类中，每个方法一个文件（`TransformLocalTransformReset.cs` 等）。

### Button 回调栈评估（只评估未动工）

需求：按钮点击只执行栈顶回调、执行一次弹一次、一次触发只执行一个回调。结论：**能做，但纯扩展方法做不到**——扩展方法不能给 Button 加接口实现、不能改实例行为、也不能存每实例状态，回调栈的"每按钮状态"必须有载体。从项目内 ugui 1.0.0 源码核实的三个事实支撑设计：

- `Button.onClick` **有公开 setter**（Button.cs 58-62 行）→ 可整体替换为只挂一个代理监听的 ButtonClickedEvent（弹栈 + 执行栈顶）。
- `Press()`（64-71 行）自带 `IsActive() && IsInteractable()` 门控，且鼠标点击与键盘 Submit（ISubmitHandler）都汇到 `onClick.Invoke()` → **走 onClick 替换方案自动获得禁用门控与 Submit 支持**，不用自己处理。
- `OnPointerClick` 是 `public virtual`、Button 未密封 → 子类化可行，但要替换预制体上的组件类型，改动面大。

**推荐方案 A**：扩展方法语法（`button.PushClickCallback(action)`）+ `ConditionalWeakTable<Button, Stack<UnityAction>>` 存每按钮的栈，首次 Push 时接管 onClick；预制体零改动，Button 销毁后 CWT 条目随 GC 自动回收，无泄漏。备选方案 B：伴随组件挂 `IPointerClickHandler`（状态在 Inspector 可见、随物体销毁，但要逐按钮挂组件，且需注意 ExecuteEvents 会派发给物体上所有该接口实现，Button 自身靠 onClick 为空保证不发事）。

待定设计点（拍板后动工）：① 首次接管时按钮已有 onClick 监听（Inspector 持久监听）的处理——清空还是叠加；② 栈空时点击的行为——静默还是 LogError 告警；③ 弹栈时序——推荐**先弹出再执行**（回调内部 Push 的新回调落在干净的栈上，留给下次点击）；④ 是否配套 `ClearClickCallbacks` / `PeekClickCallback` 等方法（同样单开脚本）；⑤ "一次触发只执行一个回调"在方案 A 下天然满足——代理监听是 onClick 唯一监听者，一次 Press() 只走一次弹栈。
