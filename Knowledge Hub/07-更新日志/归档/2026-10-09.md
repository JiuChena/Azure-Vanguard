## 升级面板材料化（目标等级 + 材料消耗）

> ⚠️ **本节模型已于同日晚被「技能书喂养重构」取代**（见文末第三轮）——UpgradeCostTable / 目标等级输入 / 直升扣耗链路整体退役；存续下来的只有 ExpToNext 曲线、SettleExp 结算口径与验证方法论。

直喂经验升级全面换成「输入目标等级 → 钳制 → 展示材料消耗 → 一次性直升扣耗」，角色页与武器页同链路。

### 数据表
- **ItemTable 补齐 5 行**（`Assets/Module/Items/Excel/ItemTable.xlsx`）：1 金币 / 2 星辉石（type 1=货币，MaxStack 99999999）+ 1001 升级手册 / 1002 突破核心 / 1003 精炼结晶（type 2=养成材料，可 sell）。此前 1001-1003 是「示例文本」占位名，本次对齐 BreakthroughTable/UnlockNodeTable 已引用的 id。
- **UpgradeCostTable 新建**（`Assets/Module/Unit/Character/Excel/Excel/` 同目录 ConfigTables 侧）：**行 L = 从 L 升到 L+1 的消耗**（1..79，覆盖 1→2 … 79→80），金币 500×L + 升级手册 2+(L−1)/2（占位公式待设计定案）。角色与武器共用一张表，上限都随角色突破 GetLevelCap 走。
- 行类 `UpgradeCostRow`（Framework.Gameplay.Unit）：id + costItems 字符串列，`CostList => ItemCost.ParseList(...)`。`SetupConfigTablesAddressables` 复用跑一遍，10 表全登记（`ConfigTables/UpgradeCostTable`）。

### 服务层（CharacterProgressionManager）
- 新 `#region 目标等级升级（材料消耗）` 四 API：
  - `GetMaxAffordableLevelAsync(unitId, fromLevel, cap)`：从 fromLevel 起逐行累加消耗与 `InventoryManager.GetCount` 对账，首次越库即止——升级面板目标输入钳制用。
  - `GetLevelUpCostAsync(unitId, targetLevel)`：聚合 fromLevel..toLevel−1 逐行消耗（同 id 合并），展示与扣耗同源。
  - `UpgradeToLevelAsync` / `UpgradeWeaponToLevelAsync`：校验目标 ∈（当前, cap] → 聚合 → `TryDeductCosts` 先验后扣（不部分扣）→ SetLevel/SetWeaponLevel + 本级经验清零。
- 旧武器喂经验链路删除（UpgradeWeaponAsync/WeaponExpToNext/BaseWeaponExpPerLevel），AddExpAsync 保留（未来战斗经验消费者）。

### UI 层（CultivatePanel + 两页 View）
- LvFromTo 模板 `{0}` = **当前等级**；InputField（Text (TMP) 的子节点）= **目标等级**。模板字符串首次读入即缓存，刷新只 Replace 占位符不动其他文字；代码支持 `{1}`→目标（当前模板只有 `{0}`）。
- onEndEdit：解析失败 → 回退上次有效值（39 → 输 −1 → 还原 39）；合法但越界 → 钳到 min(等级上限, 材料可达)。

## 物品 id string 化 + 货币重映射 + LoadProgressHub（下午段）

## 常驻通知面板 NoticePanel（下午段 #2）

### 机制（用户拍板）
- 消息缓冲队列 FIFO，逐条弹出；面板常驻（UILayer.System，开局 Preloader.Start 打开、永不关闭、ESC 覆写为空）。
- **触发规则**：容器 无消息→有消息 时 `Animator.SetTrigger(NoticeTrigger)` 一次；队列连续供弹时当前消息到点后**同帧顶上**（容器无空档）→ 不重触发；`popupInterval`（Inspector 可调，默认 2s）= 相邻两条弹出的间隔 = 单条停留时长；排空后容器回落，等下次空→有。
- **双提交通道**：① `EventNames.NoticeRequested`（string 载荷）事件总线——Core 拒绝提示走这条（Core 不依赖 UI，NoticePanel EventInit 订阅）；② 外部直接 `PanelManager.Instance.GetPanel<NoticePanel>(UIPath.NOTICEPANEL)?.Submit("...")`。

- View：`NoticePanelView`（container/noticeText 引用 + SetMessage，零逻辑）；Control：`NoticePanel : PanelBase`（队列/计时/触发/animator 哈希缓存）。

## 技能书喂养重构（暂存 + 确认结算）——升级模型第三轮

用户重设培养面板 Bot 区后整体重构：四本技能书占位，**Icon 点击一次 = 暂存使用一本**，Reduce 减使用量，Fill 自动填充到可达最高级，LevelUp 确认结算；突破改材料展示 + Breakthrough 按钮直接执行。

### 四项拍板
①升级结算=**暂存+确认结算**（点书不再立即消耗，LevelUp 才落账）；②书本图标=AD 组已就绪（`Item_Icon_Exp_Character/Weapon_0..3`）；③升级消耗=**纯书本**（信用点/升级手册退场）；④突破=材料展示 + **Breakthrough 直接执行**。

### 数据
- **ItemTable 加 `exp` 列**（旧 5 行置 0）+ 8 行技能书：角色 1011-1014 / 武器 1021-1024（角色技能书/武器技能书 I-IV，type 2，品质 1-4，maxStack 9999，exp **200/1000/5000/25000 占位**，tags sell）。

### 服务层（CharacterProgressionManager）
- 删：UpgradeToLevelAsync / UpgradeWeaponToLevelAsync / GetMaxAffordableLevelAsync / GetLevelUpCostAsync / BuildUpgradeCost / TryDeductCosts（第二轮「目标等级」链路整体退役）。
- **`SettleExp(level, exp, gain, cap, out newLevel/newExp/discarded)` 纯函数**：UI 预览与落账同口径；gain long 钳 int.MaxValue；本级起 while 扣减 `ExpToNext(lv)=ceil(80×lv^1.5)`，到 cap 溢出丢弃（原神式）。AddExpAsync 同步重构到它上面（未来战斗经验消费者自动同口径）。

- 表清单七张不变（upgradeCost → item 换位）。

## 喂养四轮修正（同日晚 #7，暂存达上限封顶 + 经验条预览）

用户两点：①暂存经验已够到等级上限后，再点书应该无效（此前只按持有量钳制，多暂存的经验落账时被 SettleExp 溢出丢弃=白点浪费）；②Lv.当前 > Lv.目标 文本后面那根进度条要接预览——不使用经验书显示当前等级当前经验进度，有暂存则显示按暂存道具可到达的 progress。

### 实现（全在 CultivatePanel.cs，两页同口径，视图类零改动）
- **上限封顶**（OnBookIconClicked）：`feedLevel >= cap` 早退之后内联一条 SettleExp 投影——`SettleExp(feedLevel, feedExp, StagedExp(·), cap, out projected, ·, ·)`，`projected >= cap` 直接 return（暂存已够推到上限，再点的书全会被溢出丢弃）。用 SettleExp 本身做判据=与落账严格同口径，无第二套阈值。
- **经验条预览**（RefreshLevelUpPreview）：SettleExp 调用捕获 `out projectedExp`（空暂存时初始化为 oldExp，语义=落点经验），文本落显后驱动现有条：
  - 无暂存：`Clamp01(oldExp / ExpToNext(oldLevel))`（即 Model.ExpProgress 口径，行为与三轮接线一致）；
  - 有暂存：`target >= cap` → 满条 1f，否则 `Clamp01(projectedExp / ExpToNext(target))`。
  - 驱动节点=两页**现有**那根条（statPage.expFillRect / weaponPage.progressFillRect，即 Base 区 Lv 文本右侧 200×20/300×20 黄条）——预制体布局已满（Exp 400w = 文本 180 + 条 200），没有第二根条的空间，故复用而非新增。
- 刷新链无需改动：暂存态每次增减走 RefreshStagedState → RefreshLevelUpPreview，条自动跟随；结算成功清零暂存后同链回落为当前进度；广播回流刷新同链。
