# 序列化与存档踩坑

> 持久化机制见 [[03-框架/数据持久化-BinaryDataManager]]，POCO 模板见 [[06-模板/模板-存档POCO]]，存档域全景见 [[04-模块/玩家数据中心]]。本篇只记事故。

## MessagePack 互操作三坑（Excel 导出工具端，2026-09-27 实证）

1. **`Dictionary<string, object>` 信封的 rows 掉进 `DynamicObjectTypeFallbackResolver` 反射序列化** → 工具端改强类型 `TableEnvelope`（`[MessagePackObject]` + `[Key("列名")]`）解决
2. **动态格式化器只认 public 类型**——工具用的类型必须 public
3. **行类成员漏标** → "`all public members must mark KeyAttribute or IgnoreMemberAttribute`"——`ItemRow.PrimaryKey` 曾漏标，补 `[IgnoreMember]`

规则收口：所有 MessagePack 参与类型的**每个 public 成员必须有 `[Key(n)]` 或 `[IgnoreMember]`**（[[06-模板/模板-配置表行类]] 六硬规则之一）。

## [Key(n)] 重排 = 旧档全部错位

`[Key]` 契约**只追加不重排**：插到中间/交换顺序会让旧档字段错位，且不报错——错位读出的是"合法的错数据"比崩溃更难查。废弃字段保留编号不删（`[IgnoreMember]` 停用语义或迁移链清理）。首字段 `version` 固定 `Key(0)`。

## id 迁移孤儿（背包/仓库条目成废链）

id 是**档案外键**：物品 `id` 值=图标地址去前缀（`icon == Item_Icon_<id>` 不变式）、单位 id int→string 全链重构（六方一致：表/代码/SO/预制体/存档/图集）。**改 id 不写迁移，旧档条目成孤儿**——背包里有条目但表查不到、图标加载不到。

- 物品 id 一经发布不可随手改（2026-10-09 曾为 AD 组命名风格迁可读英文 id，属有意决策并配了映射）
- 单位 id string 化走"[Key] 序号不变 + 旧档反序列化失败自动降级空档"的**破坏性重置**——是有意识决策，不是默认安全

## 新账号判据污染（探针提前落盘 → 假阴性）

`IsNewAccount()` 判据是 `PlayerData/` 目录不存在。任何脚本只要**提前触发存档落盘**（如探针脚本在 `OnEnable` 里保存了数据），目录即存在 → `IsNewAccount` 假阴性 → 默认角色不发。

**规则：新账号类探针/验证必须延迟发放**——先断言判据，再主动调用发放，全程不让目录提前出现；VerifyPlayerDataCenter 的清档→判定→发放→幂等断言段就是照这个顺序写的。

## SerializedProperty arraySize 扩容复制尾元素

SerializedObject 扩数组：**扩容会把最后一个旧元素复制进新槽**，不是填默认值。旧方案遗留单元素留在 [0]、新槽全复制它。修复：扩完**逐槽显式赋值**；迁移前先回读——用户可能已自配（CH0209 的 [0] 是用户自配的 Stat，用 clearPage0:false 保住；CH0221 显式清 [0]）。

## 看门狗掐断的副作用：垃圾文件

CLI 跑脚本被超时掐断时**不会执行 finally**——曾遗留垃圾 `Bag.bin` + 被清空的存档目录（下次启动按全新账号发放）。教训：

1. Verify 类脚本对存档一律**备份/还原**（先例 VerifyCharacterProgression / VerifyTrinket 三档备份）
2. 被掐断后人工检查存档目录有无半成品文件
