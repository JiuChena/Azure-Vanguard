| 轮次 | 重点 | 形式 |

## HR 面试常见问题

### 自我介绍与职业规划

- **自我介绍**: 简洁概括教育背景、技术栈、项目经验（控制在 1-2 分钟）
- **职业规划**: 短期深耕 Unity 图形/架构方向，长期定位技术专家或技术管理
- **为什么选择游戏行业**: 展现对游戏开发的热情和理解，而非单纯"喜欢玩游戏"
- **为什么离开上一家公司**: 客观正面评价，聚焦个人成长需求

### 薪资与期望

- 提前了解行业薪资水平
- 基于自身能力和市场行情合理报价
- 准备好说明期望薪资的依据

## 系统设计场景题

### 常见场景题类型

1. **系统设计**: "设计一个背包系统"、"设计一个技能系统"
2. **性能场景**: "场景中有 10000 个敌人，如何优化？"
3. **网络场景**: "设计一个多人同步的移动系统"
4. **框架设计**: "设计一个可扩展的 UI 框架"
5. **资源管理**: "设计一个 AssetBundle 管理方案"
6. **渲染问题**: "Shadow Map 出现锯齿/自阴影怎么办？"
7. **数据结构设计**: "设计一个在大地图中高效查找附近玩家的系统"

### 场景题回答框架

```
1. 澄清需求 → 问清楚具体要求和约束条件（平台、规模、性能目标）
2. 设计方案 → 提出 2-3 个方案，分析各自优缺点
3. 选择最优 → 给出推荐方案和理由
4. 细节展开 → 画架构图、写关键代码或伪代码
5. 边界讨论 → 考虑极端情况（大量数据、并发、网络异常）
6. 扩展思考 → 如何演进和扩展
```

### 典型场景题解析

#### 1. 设计一个技能系统

- **需求分析**: 技能类型（主动/被动/Buff）、释放条件、冷却、联动
- **核心设计**: 
  - 技能配置使用 ScriptableObject 或 JSON
  - 技能实例化用对象池
  - 技能效果用 Command 模式或事件系统
- **扩展性**: 如何支持技能编辑器可视化、新技能热更新

#### 2. 设计一个 AI 寻路系统

- **基础**: NavMesh 或 A* 寻路
- **分层**: 行为树（高层决策）+ 有限状态机（行为执行）+ A*（路径规划）
- **动态障碍**: NavMeshObstacle 的 Carve 模式
- **大规模优化**: 分层寻路、流场寻路 (Flow Field)、LOD 级别的 AI 更新频率

#### 3. 设计一个网络同步方案

- **选择**: 帧同步 vs 状态同步
  - 帧同步（Lockstep）: 适合确定性强的游戏（RTS、MOBA），带宽低但一致性要求高
  - 状态同步: 适合动作游戏（FPS、ACT），服务器为权威
- **优化**: 
  - 关键帧 + 增量同步减少带宽
  - 客户端预测 + 服务器和解
  - 插值和平滑处理

#### 4. Shadow Map 问题排查

- **锯齿**: 增大 Shadow Map 分辨率、使用 PCF 软阴影
- **Shadow Acne (自阴影)**: 调整 Depth Bias / Normal Bias
- **Peter Panning**: 减小 Bias
- **透视走样**: 使用 Cascaded Shadow Maps (CSM)

## 项目经验问题

### 面试官关注的维度

| 维度 | 问题示例 |
|------|----------|
| **角色与职责** | 你在项目中具体负责什么模块？ |
| **技术深度** | 遇到的最大技术挑战是什么？如何解决的？ |
| **优化能力** | 项目中做过哪些性能优化？效果如何量化？ |
| **架构能力** | 项目的技术架构是怎样的？为什么这样设计？ |
| **协作能力** | 如何与策划、美术、后端沟通协作？ |
| **工程质量** | 代码规范如何保证？如何做 Code Review？ |

### STAR 法则回答

| 步骤 | 说明 | 示例 |
|------|------|------|
| **S - Situation** | 项目背景和你的角色 | "我在一个开放世界项目中担任客户端主程..." |
| **T - Task** | 面临的任务或挑战 | "需要将大地图的 Draw Call 从 2000 降到 600 以内" |
| **A - Action** | 你采取的具体行动 | "通过 Static Batching + LOD + GPU Instancing + Occlusion Culling 组合策略..." |
| **R - Result** | 量化结果 | "最终 Draw Call 降低 70%，帧率从 30fps 提升到稳定 60fps" |

### 应对项目追问

- 不只是说"用了什么"，更要解释"为什么用"、"怎么实现的"、"有没有更好的方案"
- 展示从失败中学习的能力："如果现在重新做，我会..."
- 准备好项目的架构图，能随时画出

## 问题排查思路

### 排查方法论

```
1. 稳定复现 → 2. 缩小范围定位 → 3. 提出假设 → 4. 验证假设 → 5. 修复 → 6. 回归测试 → 7. 复盘总结
```

### 常见排查场景及工具

| 问题类型 | 排查工具 | 思路 |
|----------|----------|------|
| 帧率下降 | Unity Profiler (CPU/GPU 模块) | 定位是 CPU Bound 还是 GPU Bound，找到最耗时模块 |
| 内存持续增长 | Memory Profiler | 检查是否有资源未释放、事件未注销、闭包引用 |
| 偶发崩溃 | 日志 + Player Log | 缩小复现条件，二分法定位代码提交 |
| Draw Call 过高 | Frame Debugger | 查看每个 Draw Call 的渲染状态，找可合批的机会 |
| GC 频繁 | Profiler GC Alloc | 定位高频分配点，改用对象池/Struct/缓存 |
| 网络延迟/丢包 | Wireshark / Network Profiler | 分析协议大小、频率，优化同步策略 |

### 排查时的重要原则

- 先确认问题是**稳定复现**还是**偶发**
- **一次只改一个变量**进行对比验证
- 使用 Git Bisect 二分查找引入 Bug 的提交
- 修复后进行回归测试，防止引入新问题

## 团队协作

### 常见问题与回答策略

**如何做 Code Review？**
- 关注逻辑正确性（空指针、边界条件、线程安全）
- 关注性能隐患（GC Alloc、多余的计算、缓存缺失）
- 关注可维护性（命名、注释、模块职责清晰）
- 使用 PR 模板和 Checklist 规范化流程

**如何处理技术分歧？**
- 数据驱动决策：做 Benchmark 比较方案性能
- 列出各方案的 Pros/Cons 表格
- 考虑项目约束条件（工期、团队能力、维护成本）
- 无法达成一致时由 Tech Lead 做最终决策

**如何带新人？**
- 文档先行：提供项目 Wiki、编码规范
- Code Review 教学：指出问题的同时解释为什么
- 循序渐进：从简单 Bug 修复开始，逐步提高复杂度
- 定期 1-on-1：了解新人的困难和成长需求

## 常见行为面试题汇总

### 自我认知

- 你最大的技术优势是什么？短板是什么？如何弥补？
- 你更偏好独立工作还是团队协作？
- 描述一次技术方案的失败经历和从中获得的教训
- 如何在紧张的项目周期中保持代码质量？

### 团队与领导力

- 如何说服团队采取你的技术方案？
- 项目中遇到过最难沟通的情况是什么？
- 如何平衡技术追求与业务需求？

### 成长与发展

- 关注哪些技术博客/社区/开源项目？
- 最近在学习什么新技术？如何在项目中应用？
- 未来 3-5 年希望成为什么样的工程师？

## 加分技巧

### 系统设计题回答模板

```
1. 澄清需求 — "这个背包系统需要支持多少个物品？有堆叠吗？"
2. 画架构草图 — "数据层用 SO 配置 + 运行时 PlayerData"
3. 说关键接口 — "IItem 定义 id/name/icon, Inventory 管理 List, 事件通知 UI"
4. 提性能 — "物品图标异步加载，背包超过 100 格做虚拟列表"
5. 说边界 — "如果玩家断网时使用物品，本地先扣减，服务端校验兜底"
```

### 初级/中级/高级面试差异

| 级别 | 考察重点 | 典型问题 |
|------|---------|---------|
| 初级 | API 熟练度、基础概念 | MonoBehaviour 生命周期、值类型 vs 引用类型 |
| 中级 | 系统设计、优化思路 | 设计一个背包/技能系统、Draw Call 优化 |
| 高级 | 架构决策、底层原理 | 帧同步 vs 状态同步选型、GC 机制深度 |

### 压力测试 & 陷阱题

- **"你最大的缺点是什么？"** → 说一个真实的但可弥补的缺点 + 你在如何改进
- **"你为什么离开上一家公司？"** → 不抱怨，说成长需求
- **"你的项目上线后出了严重 Bug，你怎么办？"** → 先止损(回滚/热修) → 再排查 → 最后复盘
- **"如果你和主程意见不一致？"** → 数据驱动:做 Benchmark 对比方案 → 列 Pros/Cons → 让决策者有依据

### 薪资参考

- 薪资受城市、公司规模、项目类型影响差异很大，面试前建议去脉脉/OfferShow/牛客查同期同岗位行情
- 谈薪技巧：先让对方给范围，或报期望时留谈判空间；关注 Total Package（基础+年终+股票/期权+补贴）
- 校招可参考各公司官方发布的薪资带
