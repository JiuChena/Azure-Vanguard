## C++
#### **源文件从文本到可执行文件经历的过程**
![[Pasted image 20260423221727.png]]
**1、预处理阶段（.cpp->.ii）**
预处理阶段主要负责处理以#开头的预处理指令，包括
- 宏展开：将#define定义的宏替换为对应的值
- 头文件包含：将#include包含的头文件内容插入到当前文件中
- 条件编译：根据#ifdef、#ifndef、#if等条件编译指令决定哪些代码需要编译
预处理阶段生成.ii的中间文件，包含了所有宏展开和头文件包含后的完整源代码
**2、编译阶段 （.ii->.s）**
编译器将预处理后的源代码转换为汇编代码，这个过程包括：
词法分析 -> 语法分析 -> 语义分析 -> 优化 -> 代码生成
这个阶段会生成扩展名为.s的汇编文件，包含了对应的汇编指令
**3、汇编阶段（.s->.o或.obj）**
汇编器将汇编代码转换为机器代码，生成目标文件。这个阶段：
- 将汇编指令转换为二进制机器指令
- 生成符号表，记录函数和变量的地址信息
- 生成重定位信息，用于链接阶段解析外部符号
目标文件为二进制代码，我们不能直接打开查看，也不能直接运行，因为可能包含对外部符号的引用。例如
- 代码中调用了 `std::cout`，但 `cout` 的实际定义在 `iostream` 库中
- 使用了动态库中的函数，需要链接器在运行时加载
- 调用了其他目标文件中定义的全局变量
这些外部符号需要在链接阶段才能解析
**4、链接阶段**
链接器将多个目标文件和库文件合并成最终的可执行文件：
- 符号解析：解析外部符号引用，找到对应的定义
- 重定位：调整代码和数据的地址
- 库链接：链接静态库（lib）和动态库（dll）
链接可以分为：
- 静态链接：将库代码直接合并到可执行文件中
- 装入时动态链接：在装入时将库代码加载到内存中
- 运行时动态链接：在运行时将库代码加载到内存中
至此就得到了一个可执行文件

#### **动态链接库和静态链接库的区别**
二者之间的区别在于**链接和加载的时机不同**
静态链接库是在编译链接阶段将库里的目标代码直接复制到可执行文件中，生成的程序体积较大，但是对运行时对外部库的依赖少，部署较简单。缺点是，库如果更新，程序需要重新编译或重新链接
动态链接库是在程序运行时由系统进行加载，程序本身只保存对库的引用，所以程序体积小，多个程序可以共享同一个动态库。缺点是运行环境中必须能找到对应版本的动态库，否则程序将启动失败

#### C++内存
内存分区
代码区 (.text): 存放程序编译之后的机器指令。
全局/静态区：存放全局变量，静态变量。这部分内存在程序启动时分配，程序结束时释放
常量区：通常存放字符串常量、const修饰的全局常量
堆区：动态申请的内存放入堆区，速度慢，但是空间大
栈区：函数调用过程中的局部变量、函数参数、返回地址等。栈由系统分配和释放内存，速度快，但空间小

注意并不是所有被const修饰的变量都在常量区，一般来说~={red}全局const、静态const、字符串字面量=~会放入常量区。
- 函数内部的普通const，如果需要存储，通常存储于栈
- 被符号表优化：一些编译器常量表达式，会被编译器直接优化。如下代码

#### new/delete和malloc/free

**二者之间的区别**
malloc/free为申请/释放内存，malloc的返回值为void*，分配失败时返回NULL/nullptr
new/delete 会调用 operator new/operator delete 来申请和释放原始内存，同时调用构造/析构函数，new的返回值为具体类型，更加安全。分配失败抛出 std::bad_alloc异常

**delete怎么知道要使用多大的空间，这些信息存储在什么位置**
delete 释放内存时，底层内存分配器通常会通过用户指针找到隐藏的分配信息。

**`delete[]` 与delete的区别，基本数据类型的数组使用delete可以释放完全吗**
前者用于释放数组，后者用于释放单个对象的内存。前者可以释放数组内存的原因时，`new[]`时会保留数组元素的个数，前者可以获取到这个信息，对数组中的元素进行遍历释放。
 基本数据类型数组虽然没有析构函数，用 delete 可能表面上能释放，但 `new[]` 与 delete 混用属于未定义行为，不能保证释放完全或行为正确。

**vector的capacity和扩容机制，使用时需要注意什么**
当vector的size == capacity时，再次插入元素会触发扩容，一般来说扩容时申请的内存大小是原capacity的1.5倍/2倍，将vector中的元素拷贝到新内存中。

使用时需要注意，扩容之后原迭代器将失效

**如果扩容时会引发自定义类型的复制构造，C++会使用什么机制来避免这一点**
C++在进行拷贝时会尽量使用移动构造函数，如果没有或移动构造函数没有声明noexpect则使用拷贝构造函数

**vector和list的区别，内存、复杂度等**
vector通过动态数组实现，list通过双向链表实现
vector的内存是连续的，list的内存是分散的
vector支持随机访问复杂度为O（1），对vector进行尾部的插入和删除时间复杂度为O(1)，对其他部位进行插入和删除时间复杂度为O(n)，查找的复杂度为O（n）
list不支持随机访问，头/尾部插入删除的时间复杂度都为O（1），其他部位为O（n）,查找复杂度为O(n)

vector 适合随机访问多、尾部增删多的场景。
list 适合已知节点位置后频繁插入删除的场景。


**二叉排序树、平衡二叉树、红黑树的设计思想**
二叉排序树，在构造时依据左<根<右的大小顺序。
查找的时间复杂度一般为O(log n),
但是对于一些排序会退化为链表，复杂度变为O（n)

平衡二叉树：是一种自平衡的二叉搜索树。
通过旋转调整树高，避免退化成链表
典型代表是 AVL 树。
AVL 树要求任意节点左右子树高度差不超过 1，因此查找很快，树更严格平衡。
由于是严格的平衡，因此查找的复杂度为O(log n)

红黑树：也是一种自平衡的二叉搜索树，不过平衡条件并不严苛
特点为：
根节点与叶子节点都为黑色（根叶黑）
不存在两个连续的红色节点（不红红）
任一节点到叶的所有路径的黑节点个数相同 (黑路同)
由于红黑树的性质，所以红黑树的最长路径不会超过最短路径的两倍
因此查找复杂度为O(log n)

红黑树的插入操作
规定：插入节点为红色
那么插入节点只能违反~={red}**根叶黑**=~与~={red}**不红红**=~这两条性质
- 如果违反根叶黑（即插入根节点为红），那么直接将其变黑即可
- 如果违反不红红，则需要根据父节点的爷爷节点的另一个孩子（叔叔节点）的颜色判定。
	- 如果叔叔节点为**黑**，则需要判断**从爷爷到当前节点的类型（LL,RR,LR,RL）进行翻转，然后对爷爷节点和中心点变色即可**。
	- 如果叔叔节点为~={red}红=~，则**直接将爷爷节点、父节点、叔叔节点颜色反转**，同时接着对**爷爷节点进行判定**。

#### **strcmp与memcmp 、strcpy、strncpy、memcpy和memmove的区别**
strcmp：比较两个C风格的字符串，也就是 `char*、char[]` 这类以 `'\0'` 结尾的字符串。
原理是一个char一个char进行对比，遇到 '\0' 就认为字符串结束，并停止比较。比较规则是按照ASCII/字典序进行比较。

> [!NOTE]
> 注意：
> `char[]`类型的变量不能直接使用`==`进行比较，因为其比较的是地址，不是字符串内容。而`string`可以，因为`string`重写了`==`操作符
> `strcmp`不能传入两个`string`类型，如果一定要用 `strcmp`，`string`变量可以通过`.c_str()`转成 C 风格字符串

memcmp：用来**按字节比较两块内存**。
```
函数原型为：int memcmp(const void *a, const void *b, size_t n);
表示比较 a 和 b 的前 n 个字节。
```

> [!NOTE]
> 注意：
> - memcmp原理是**按字节比**，不一定适合所有类型的“逻辑相等”判断，尤其是结构体、浮点数这类对象。
> - memcmp返回值为正只表示第一处不同字节中，前者更大，不代表长度更长

与strcmp的比较：
- 原理不同：strcmp的原理是比较char遇到'\0'会停止比较，memcmp比较的是字节，不会因为遇到'\0'而停止
- 适用范围不同：strcmp只适用于C风格的字符串的比较，memcmp 适用于内存块比较，比如字符数组、部分二进制数据、某些简单数组。


strcpy:**字符串复制函数**，用于把一个**C 风格字符串**复制到另一个字符数组中
```
函数原型：char* strcpy(char* dest, const char* src);
表示将src中的字符复制到dest中，包括`'\0'
```

> [!NOTE]
> 
> 注意：在使用时需要注意dest要有足够的内存，否则可能越界

strncpy:**指定长度的**字符串赋值函数。
```
函数原型：char* strncpy(char* dest, const char* src, size_t n);
将src中的前n个字符复制到dest中
```

> [!NOTE]
> 注意：
> - 同样，dest要有足够的内存，否则可能越界
> - 如果src的长度小于n，则缺少的元素使用'\0'补上
> - 如果src的长度大于n，则不会自动补'\0'
> 由于这个机制的存在，dest数组可能不是有效的字符串，需要手动设置'\0'

memcpy:是**内存复制函数**
```
函数原型： void* memcpy(void* dest, const void* src, size_t n);
表示把 src 的前 n 个字节复制到 dest。
```

> [!NOTE]
> 注意：
> - dest 必须有足够空间，否则可能越界
> - dest和src的内存空间不能重叠
> - 如果内存区域可能重叠，应使用 memmove

memmove：是**内存移动函数**，也是按字节复制内存，但它**可以处理源内存和目标内存重叠**的情况
会根据目标区在源区的位置关系来选择复制方案（从前往后复制，从后往前，使用临时缓冲区）
```
函数原型： void* memcpy(void* dest, const void* src, size_t n);
表示把 src 的前 n 个字节移动到 dest。
```
如果src与dest不重叠，那么就和memcpy的效果相同，如果有重叠，则src的内容可能会被改变。

#### **lambda捕获**
lambda的语法
```
 [捕获变量](函数变量) -> 返回值类型 {
      // 方法体
  };
```
使用方法如下
```
 //需要使用一个变量来承接
 auto add = [](int a, int b) -> int {
    return a + b;
	};
 //之后这个变量就可以像函数一样被调用了
 cout << add(3, 5) << endl;  // 8
```
这样使用的原因C++ 的 lambda 表达式在底层会被编译器转换成一个匿名的闭包类对象，这个类重载了 operator()，所以本质上它就是函数对象（仿函数）的简写形式。
lambda的捕获方式有以下几种
```

[var] : 显式值捕获变量var
[&var] : 显式引用捕获变量var
[=] : 值捕获：以拷贝的方式捕获外部所有变量（默认不可修改）
[&] : 引用捕获：以引用的方式捕获外部所有变量（默认可修改）
[=,&var] : 默认值捕获，但是显式引用捕获变量var
[&,var] : 默认引用捕获，但是显式值捕获变量var
[this] : 捕获当前类的this指针（用于类成员内的lambda）
```

默认情况下，值捕获的变量在lambda内部不可更改，即使是捕获的拷贝值
但是可以通过mutable关键字做到更改值捕获

```
int a = 10;
auto f = [a](int a,int b) mutable ->int{
	 a++;
	 return a+b;
 }
```

值捕获闭包与引用捕获闭包
一般来说值类型的闭包是安全的，但是要警惕悬空指针
引用捕获闭包是不安全的，例如
```
auto f(){
	int a =10;
	return [&a]()->int{return ++a;};
}
```
上面这个例子里的闭包是不安全的，因为这里引用了一个局部变量，但是lambda又是在作用域外执行的，这就会导致lambda中保存的是一个悬空引用，执行时就会报错

### **C#/.Net内存结构**
栈：存放方法调用信息，局部变量，值类型数据，引用变量本身的地址

静态区 / 方法表相关区域：存放静态字段、类型元数据、方法信息等

### **值类型与引用类型**

### **值传递与引用传递**
 值传递是将实参的值复制一份传递给形参，方法内部对形参的修改不会影响实参；引用类型变量作为普通参数传递时，传递的是引用值的副本，不是引用本身，所以本质仍是值传递；
 例如：
```
  void Test(Person p)
  {
      p = new Person();
      p.Name = "Tom";
  }

  Person p1 = new Person();
  p1.Name = "Jack";

  Test(p1);
  Console.WriteLine(p1.Name);   // Jack
```
### **ref、out和in**
被ref、out和in修饰的参数都会按照引用传递，所以都可以影响到实参
ref要求实参在调用方法前已经有赋值
out不要求实参在调用方法前赋值，但要求方法内部返回前必须对其赋值
in修饰的参数虽然是引用传递，但是是只读的，通常用于传递一些较大的值类型数据，减少拷贝开销
### **is与as**
is是C#中的类型判断器，例如a is B,则表示判断变量A是否是B类型或是B类型的派生类，返回bool值
as 是安全类型转换运算符，例如 A a = b as A;  表示把 b 转换为 A 类型。如果 b 本身是 A 类型，或者是可转换为 A 的类型，则转换成功；否则结果为 null。
C#还有强制转换，语法与C中的强制转换相同，例如 A a = (A)b;
如果转换成功则返回目标类型对象，如果转换失败则抛出异常

### **反射的原理**
程序在运行时获取类型信息，并动态操作对象和成员
C#程序编译之后，类型信息不会消失，而是会以元数据的形式保存在程序集中，运行时可以通过反射读取这些信息，从而直到一个类有哪些构造方法、属性、字段、方法、接口等，并且能够动他创建对象、调用方法

优点：灵活，拓展性强
缺点是：性能低：由于要在运行时解析和操作元数据，比直接调用慢；类型安全性差：很多错误只能在运行时发现，编译阶段无法检查；增加代码复杂度与调试难度

要使用反射首先要获取通过typeof来获取类型
通过该类型获取TypeInfo
然后就可以通过类型信息获取方法、成员变量、构造函数、属性等
如果要调用方法
首先要获取对应方法的MethodInfo
然后要区分静态方法与动态方法调用

```
Type type = typeof(Test);  
TypeInfo typeInfo = type.GetTypeInfo();  
MethodInfo[] methodInfos = typeInfo.GetMethods();  
MethodInfo showMethodInfo = typeInfo.GetMethod("Show");  
FieldInfo nameFieldInfo = typeInfo.GetField("name",BindingFlags.NonPublic|BindingFlags.Instance);  
ConstructorInfo constructorInfo = typeInfo.GetConstructor(Type.EmptyTypes);  
  
object test = constructorInfo.Invoke(null);  
nameFieldInfo.SetValue(test, "测试名称");  
showMethodInfo.Invoke(test,null);
```

### **事件与委托**
委托可以使用delegate进行定义，其为类类型。
事件是对委托的一个包装器，通过event关键字进行定义，后面声明委托类型
委托是对方法的引用和封装，可以直接调用；事件是对委托的进一步封装，只允许外部订阅和取消订阅，不能直接触发。事件通常用于对象之间的消息通知，因此比委托更安全。
Action与Func为.Net提供的泛型委托，二者的区别为Action适用于无返回值的函数，Func适用于有返回值的元素，Func的最后一个参数类型为返回值类型
EventHandle其是.Net为我们定义的一个委托类型，其参数为object与EventArgs，前者用于传递信息发送者，后者用于传递信息内容

### 协程与线程

协程是协作性调度，协程主动在await、yield等位置让出执行权
线程是抢占式调度，操作系统可以在任意时刻切换线程
协程虽然是协作性调度，但是不一定会阻塞线程，它通过await、yield来交出执行权并保存运行位置，直到条件达成，然后再恢复协程，接着运行
协程相当于是运行在线程上的可暂停函数
并发，并行，异步
并发，同一时间段内执行多个任务，不要求同一瞬间同时执行，而是多个任务交替推进。看起来都在运行就是并发
并行，同一时刻真的有多个任务同时执行，通常需要CPU多核
并行一定是并发，并发不一定是并行
异步，发起一个任务后，不一直等它完成，而是先去做别的事；等操作完成后再回来处理结果。例如处理网络请求，处理IO操作，都可以使用异步来做
