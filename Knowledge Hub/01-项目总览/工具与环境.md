# 工具与环境

Claude/Agent 在本项目的开发工作流。踩坑细则见 [[08-踩坑与排查/UnityCLI工作流]]。

## UnityCLI（跑编译与脚本）

```bash
"C:/Users/jiiuc/AppData/Local/Unity/bin/unity.exe" command run_script \
  --project-path "D:/Unity3D/Unity Programs/Azure Vanguard" \
  --file AgentScripts/<脚本>.cs --entry <类名>.Run --timeout 90
```

- **必须带 `--project-path`**（双编辑器实例场景）
- 入口约定：`public static string Run()`，返回结果字符串
- 脚本放项目根 `AgentScripts/`（不进编译域，无 IDE 补全——**using 清单按命名空间全量过**，见 [[08-踩坑与排查/UnityCLI工作流]]）
- **成败判定三件**：console groundTruth（compilationFailed/consoleErrors）+ dll 二进制 grep（字面量须 UTF-16LE；mtime 基线须写文件前取）+ 脚本自身返回断言

## 编译三重验证（改 .cs 后必做）

1. **dll mtime 基线**：取 `Library/Bee/` 产物或 `Temp/Bin/` 下业务 dll 修改时间（写文件**前**取）
2. **刷新+符号 grep**：UnityCLI 触发重编译后，对 dll 二进制 grep 新增类名/字面量（UTF-16LE 编码）确认编译产物已更新
3. **console groundTruth**：run_script 返回的 compilationFailed / consoleErrors 无错

> "A parse check is not a run."：玩家可观察的变化要 Play 观察 + 截图存 `production/qa/evidence/`。

## 工作分工约定

每项工作开始前明确分工，文档/SOP 中用三类标注：

- 🤖 **Claude 自动化**——写码/脚本/验证，可直接做
- 🖐 **用户手调**——编辑器操作（场景摆放/Inspector 调参/出图/连线预制体动画）
- 📐 **设计拍板**——需用户给方案才能做；未拍板项进 [[05-玩法设计/设计挂账]]

边界：AI 只负责脚本编写和逻辑校验（可运行测试），不自行拼场景 UI/摆 GameObject/组 Prefab 层级；通过 `[SerializeField]` 预留用户接入点。改基础框架（Core.Gear/Core/Expand 框架性文件）必须先征得用户同意。禁止自行安装任何插件或包。

**编辑器扩展残留零容忍（2026-10-24 定规）**：未经用户允许，不得把拓展功能（临时工具/调试器/一次性 authoring 脚本）留在 Unity `Tools/` 工具栏下。可以临时编写使用，**用完即清理**——删除脚本及 `.meta`（或摘除 `[MenuItem]` 注册），不允许留下残余菜单项。需要长期保留的工具（用户确认在用的编辑器窗口，如 `Tools/Sprite Atlas Injector`）须先经用户允许并在本页登记。示例：`Assets/Editor/CH0221FX/` 律动特效 authoring 工具（4 个 `Tools/CH0221 FX/` 菜单）已完成使命，2026-10-24 整文件夹删除。
