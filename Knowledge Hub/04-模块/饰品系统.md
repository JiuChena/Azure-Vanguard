## 规则定稿（用户拍板，勿再议）

- **定位**：装备系统。装备**不可升级、不可洗练**，掉落即定形；词条数值全部表配死（无公式）
- **三自由格**：角色身上最多穿 3 件，格子不绑类别——可三件同类别、可两件相同 id（各占一件实例）
- **品质 1-5**：每款装备的品质维度，表配死；品质只影响数值，不影响合奏
- **副词条固定 3 条**：固定数值、比主词条小，无其他系统
- **合奏（套装）只认三件套**，触发条件 = **三件装备同 ensembleId 且三件类别互不相同**（三个帽子不触发、两帽子+一手表也不触发——"三种不同的才行，不同款帽子也是帽子"）。两件/一件无任何效果。**一件款式只支持一种合奏**（多合奏已否决）
- **主属性键复用现有属性键**（atk/hp/def/crit_rate/crit_empower/energy_recharge/dmg_bonus/burst_pierce…）；要新键必须 CharacterStats/结算器同步新增（动 Core 时另征同意）
- **穿脱无限制**：随时穿随时脱，无条件
- **持有者写在装备本体**（用户拍板，否决反查 API）：装备那一刻写入 wearerId，背包页显示"谁在穿"直读字段→按角色 id 查小头像

## 三 id 语义

| id | 存在哪 | 用途 |
|---|---|---|
| **itemId** | 实例上存储 | **权威**。查表派生一切（类别/合奏/词条/图标） |
| **category 类别 id** | 表列（string，开放清单） | 合奏触发的"类别互异"判定；背包筛选。起步 9 类：Badge/Bag/Charm/Gloves/Hairpin/Hat/Necklace/Shoes/Watch |
| **ensembleId 合奏 id** | 表列（空=无合奏） | 三件套判定；**挂款式级**——同款式（Watch_Tier1）所有品质行同值，导出断言校验 |

## 实例模型（与背包计数模型的分界）

- 装备是**逐件实例**：`instanceId`（ulong 自增）+ `itemId` + `wearerId`（空=未穿）。同 itemId 两件 = 两条实例，可分别穿给两个角色
- **单一事实源 = wearerId**：角色身上三件 = 扫实例 `wearerId == characterId`（≤3 由装备时校验保证）。**CharacterEntry 零改动**，穿/脱只动 wearerId，无双写
- **存档**：独立存档 `PlayerData/Trinket/Trinkets.bin`（BinaryDataManager，带 version + nextInstanceId）。**InventoryManager 不动**，装备不进背包计数
- 装备已穿时再穿给另一角色：默认拒绝（Notice 提示 "Already worn"），先脱再穿

## 表结构（Assets/Module/Unit/Trinket/Excel/ → ConfigTables 组）

**TrinketTable**（行 = 款式 × 品质，显式行）：

| 列 | 说明 |
|---|---|
| id（主键，string） | `Watch_Tier1_Q3` 形态：款式 + `_Q<品质>`（已定稿） |
| name / desc | 显示名/描述（显示名走表，代码不写中文） |
| category | 类别 id（9 类起步） |
| kind | 款式（`Watch_Tier1`，即图标名去 `Trinket_Icon_` 前缀） |
| quality | 1-5 |
| ensembleId | 空=无合奏；同 kind 全行同值（导出断言） |
| mainStatType / mainStatValue | 主属性键 + 值 |
| subStat1Type/Value … subStat3Type/Value | 副词条固定 3 条 |
| icon | 图标地址 = `Trinket_Icon_<款式>`（品质共享图标，品质走 UI 边框色） |

**EnsembleTable**（行 = 合奏）：`id`(主键) · name · desc · `bonus`（解析列，属性键值对 `key:value;key:value`，tags/ItemCost 同款容错解析）

设计约束：一个合奏的三件套必然跨 3 个类别（触发条件决定），组套装时选 3 个不同类别的款式。

## 属性结算接入

- `CharacterProgressionManager.CalculateStatsAsync` 载荷 += **TrinketStatContribution**：在穿 3 件的主+3 副词条按现有加法区口径并入（同 WeaponStatContribution 先例）+ 生效合奏的 bonus 并入
- 合奏判定纯函数 `EvaluateEnsemble(在穿实例列表)`：count==3 && ensembleId 全同 && 类别互异 → 返回 ensembleId / null
- 计算器按键路由——平面键 atk/hp/def 并入基数（同武器白值口径：等级系数后、百分比乘区前），百分比键走 AccumulateBonus 加法区，均不受 bonusIds 归属过滤；公式 = Floor((基础×等级系数 + 武器白值 + 装备平面) × (1+Σ同键百分比))

## TrinketManager API

`Grant(itemId, count)`（发实例）· `Equip(instanceId, characterId)`（校验：实例存在/未在穿/该角色在穿 <3）· `Unequip(instanceId)` · `GetWornBy(characterId)` · `GetWearer(instanceId)` · `Snapshot()`；`EventNames.TrinketUpdated` 广播（穿脱发放后 UI 自刷）。玩家拒绝走 `NoticeRequested`：Already worn / Trinket slots are full。测试发放：TestItemGranter 扩展发实例（挂账）。
