# 物品 / 背包 / 货币

代码位置：`Assets/Scripts/CSharp/Core/Gameplay/Item/`（ItemRow / ItemFeatureCatalog / ItemFeatures）+ `Core/Gameplay/Inventory/InventoryManager.cs`。ItemTable 表：`Assets/Module/Items/`（源 Excel + 产物 bytes/json）。新加物品流程 → [[02-流程SOP/SOP-新加物品与配表]]；配表管线 → [[02-流程SOP/SOP-数据表流水线]]。

## 物品模型（2026-09-27 定稿）

- **一个物品 = 静态定义（ItemTable）+ 玩家持有量（运行时数据，服务端权威）+ 行为（tags → 代码）**。玩家背包存 `itemId → count`，货币与道具同构同表
- **货币是物品**：type 之一，余额 = `InventoryManager.GetCount(货币ItemId)`；`CurrencyIds`（Gold=1 / StarlightStone=2）。**体力例外**——时间恢复/上限是玩家字段，不走背包
- **网络只传 id+count**：背包数据（存档/网络消息）永远是 `List<{itemId, count}>`，属性一律查表，不拷贝进背包数据
- **type(int) 与 tags(string) 分工**：type = 物品是什么类（数据关联/分类筛选，装备将来另开 EquipmentTable 按 id 关联）；tags = 有什么功能（行为/UI 分发）

## 背包哑台账（YAGNI 拍板）

InventoryManager 只管 `itemId→count`，不引 DataTableManager 依赖；物品名/图标查询层等第二个消费者（背包格子/详情页 UI）出现再建，届时需处理 DataTableManager 的异步预加载与同步查询。

## tags 行为分发

- **tags 约定**：Excel 一格逗号分隔多标签（`usable,sell,batch`），空 = 纯展示；解析后精确匹配（不做大小写不敏感），未命中 `ItemFeatureCatalog.TryCreate` 记 LogError 跳过
- **`ItemFeatureCatalog`**（Core/Gameplay/Item/）：标签常量 `ItemFeatureTags`（usable/sell/batch，同 BehaviorKey 惯例）+ `Dictionary<string, Func<IItemFeature>>` 注册表（惯例同 BetterHSMAbilitySchemeCatalog）；`IItemFeature.Execute()` 目前 TODO log 占位，等 UseItemRequest/SellItemRequest 网络通道
- 购买/使用/出售都是操作请求走服务端裁决（[[04-模块/服务端与网络【骨架】]]）

## ItemRow（首个行类）

`Framework.Gameplay.Item`（Core/Gameplay/Item/ItemRow.cs）：id/name/icon/type/quality/maxStack/price/sellPrice/desc/tags；public 属性 `PrimaryKey`/`TagList` 已标 `[IgnoreMember]`。**icon 不变式：icon 地址 = `Item_Icon_<id>`**（重键后旧档背包条目会成孤儿——id 是主键更是档案外键，改 id 必须同步迁移旧档）。
