# 角色养成系统（数值体系 + 服务层）

代码位置：`Assets/Scripts/CSharp/Core/Gameplay/Progression/`（CharacterProgressionManager / CharacterStats / CharacterStatsCalculator / ProgressionOpJournal）+ 行类 `Core/Gameplay/Unit/`。表：`Assets/Module/Unit/Character/`。玩家数据侧（仓库）见 [[04-模块/玩家数据中心]]；养成 UI 见 [[04-模块/面板-CultivatePanel]]；操作规则拍板见 [[05-玩法设计/玩法规则]] §养成操作规则。

## 分层边界

- **SO = 表现绑定**（图标/BEclip/Prefab 等资产引用）；**数值 = 实时变动（调平衡）→ Excel 表**。判定标准一句话：**服务端要不要读**——服务端读不了 SO，数值必须全走表（战报校验要服务端复算）
- **UnitConfig 聚合根**（用户设计）：UnitConfig 实时引用该角色全部表 .bytes，入队加载一个入口全部到位、卸载跟随释放；表反序列化结果按表名进 DataTableManager 缓存全队共享（8 人编队不重复反序列化，EnsureTable 注入入口待接）。基类 `UnitConfig`（`string unitId` + unitName + behaviorClips）→ `CharacterUnitConfig`（dataTables[] 五张共享表 + breakthroughTable，突破仅角色有）；敌人 SO 将来另开子类。基类非 abstract（保持旧资产可加载），约定不直接建基类资产

## 表清单（角色域，Assets/Module/Unit/Character/）

| 表 | 列 | 说明 |
|----|-----|------|
| CharacterTable | id/name/rarity/profession/camp/cost/hp/atk/def/atkInterval/range/moveSpeed + normalAtkId/skillEId/skillQId/talentIds/bonusIds | 属性直进主表（与角色 1:1 不拆表）；引用列逗号分隔 |
| LevelTable | level/multiplier | 全角色共享成长曲线（1~80）；升级经验公式写业务逻辑（用户拍板不进表） |
| SkillTable | skillId/name/type/maxLevel/cooldown/cost/effectIds/desc | 技能骨架 |
| SkillEffectTable | effectId/effectType/target/range/value/growth/duration/desc | 一效果一行 |
| SkillLevelTable / UpgradeCostTable | （后续扩充，盘上已有） | 技能升级/升级消耗 |
| UnlockNodeTable | nodeId/type/effectKey/effectValue/cost/desc | talent=行为逻辑键（BehaviorKey 惯例）；bonus=属性名（hp_pct/atk_pct/crit_rate/crit_dmg…） |
| BreakthroughTable | breakStage/levelCap/costItems/unlockNodeIds | 行=阶段，全角色共享，levelCap 40→80 |

- 行类 `Framework.Gameplay.Unit`（Core/Gameplay/Unit/）：CharacterRow/LevelRow/SkillRow/SkillEffectRow/UnlockNodeRow/BreakthroughRow + `ItemCost`（`itemId:count` 逗号分隔的消耗条目解析）
- **id 编码**：unitId = `CH`+三位数字（如 CH0221）；skillId = 数字码×100+槽位（01普攻/02E/03Q，如 22102）；effectId = skillId×100+序号（如 2210201）。看 id 知归属，零映射表
- **技能两层**：多效果技能 = SkillTable 骨架 + SkillEffectTable 多行（"回自身20%+回全队10%+5×5减速50%" = 3 行）；等级成长跟效果走 `value + growth×(level−1)`，**不逐级建行**；运行时 effectType → 执行器注册表分发（同 ItemFeatureCatalog 惯例）
- **突破**：costItems 沿用 `itemId:count`（金币=1）；unlockNodeIds = 突破附带解锁 bonus 节点（原神式），与 UnlockNodeTable.cost 独立材料解锁并存（判定：是否出现在突破表里）
- 种子工具 `Tools/CharacterTableSeeder/`：生成含示例数据的 xlsx，已存在跳过保护策划数据

## 乘区公式（2026-10-06 服务层落地口径）

`最终属性 = floor(base × levelMult(level) × (1 + Σ同键百分比加成))`；养成新维度 = 加乘区/加区，战斗侧零改动。

## 养成服务层（Framework.Gameplay.Progression，2026-10-06 落地）

DataTableManager 首个真实消费者；仓库保持哑台账，规则与校验全在本层。

| 文件 | 职责 |
|------|------|
| `CharacterStats` | 只读属性快照：MaxHp/Atk/Def/CritRate/CritDmg |
| `CharacterStatsCalculator` | 纯函数计算器，依赖全参数注入（不碰单例，可独立测试） |
| `CharacterProgressionManager` | 懒加载单例，升级/突破/节点解锁/属性结算业务入口 |

- **公式（2026-10-06 拍板）**：本级所需经验 = `80 × level^1.5` 向上取整（`ExpToNext` 静态方法，UI 经验条分母共用；BaseExpPerLevel/ExpCurvePower 常量单点可调）；**到达 levelCap 后溢出经验丢弃**（原神式），突破后继续吃。stage0 无突破表行 → `InitialLevelCap = 20` 常量
- **属性**：`最终 = floor(base × levelMult × (1 + Σ同键百分比加成))`（double 累积，FloorToInt 带 1e-4 容差防 float 表示误差掉 1）；暴击加法区 `0.05 + Σcrit_rate`、`0.5 + Σcrit_dmg`（基础常量，表无此列）；加成只认本角色 bonusIds 列出的 bonus 节点，talent/外来节点跳过；starMult v1 恒 1（星级乘区随抽卡接入）。武器/饰品贡献由调用方并载荷（白值并基数、百分比走加法区，见 [[04-模块/饰品系统]]）

| API（CharacterProgressionManager） | 说明 |
|-----|------|
| `EnsureReadyAsync()` | 确保四张养成表加载（缓存短路，重复调用无代价）；同步查询前 await |
| `ExpToNext(level)`（static） | 本级所需经验；参数非法 LogError 返 0 |
| `AddExpAsync(unitId, amount)` | 本地循环结算可连升 + 一次落账（SetLevel+SetExp 各一次），返回 `LevelUpResult{Success/OldLevel/NewLevel/DiscardedExp}` |
| `BreakthroughAsync(unitId)` | 等级达当前上限 + 材料够 → 整体扣耗（校验先行不做部分扣除）→ breakStage+1 → 免费解锁附带节点 |
| `UnlockNodeAsync(unitId, nodeId)` | 突破附带节点拒单独解锁；重复解锁幂等拒绝（扣耗前拦截）；独立消耗解锁 |
| `CalculateStatsAsync(unitId, star=1)` | 属性结算单一入口；LevelTable 脏档越界按 1.0 兜底并报错 |
| `GetLevelCap(breakStage)` | 同步查询；表未加载或行缺失按 20 兜底并报错 |
