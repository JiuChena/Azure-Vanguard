# 玩家数据中心

代码位置：`Assets/Scripts/CSharp/Core/Gameplay/Player/`（PlayerInfoManager / CharacterWarehouseManager / PlayerDataCenter）+ `Core/Gameplay/Inventory/InventoryManager.cs`。持久化机制见 [[03-框架/数据持久化-BinaryDataManager]]。

**架构决定：分域档案 + 门面，不搞单文件大档**。本地每域一个 Manager + 一个带版本号的 MessagePack 文件（容错好、保存粒度小）；"将来上服务器的单文档"由上传时组装，不要求本地是单文件。数据中心钉死三样统一：**条目形状**（[Key] 契约只追加不重排）、**版本策略**（首字段 version + 迁移链）、**入口**（Manager 单例唯一存档者，变更即保存）。

### 新域落地模板（照此三步）

1. Data 根对象（version + [Key] 契约只追加）
2. Manager 单例（唯一存档者、变更即保存、`LoadData` 内 Normalize 防脏数据：同 id 留首个、字段下限防御、去重）+ EventNames 事件
3. 把 SaveData/LoadData 挂进 `PlayerDataCenter` 两个批量方法

## PlayerInfo / PlayerInfoManager（2026-09-15）

`PlayerInfo` 字段（`[Key]` 顺序固定）：`version`、`avatarName`（头像图集内 sprite 名）、`nickName`、`level`、`exp`、`maxExp`。

`PlayerInfoManager`（懒加载单例，**变更即保存**）：

| API | 说明 |
|-----|------|
| `Data` | 只读获取当前 `PlayerInfo` |
| `SetNickName(string)` | 改昵称；空串拒绝并 LogError |
| `SetAvatar(string)` | 改头像，存 sprite 名 |
| `AddExp(int)` | 加经验并循环结算连升；升级后 `maxExp` 暂不变化，**接入等级曲线表后在此结算** |
| `SaveData()` / `LoadData()` | 手动持久化 |

## 角色仓库（CharacterWarehouseManager，Core/Gameplay/Player/）

`CharacterEntry` 字段 = 养成条目定稿形状落库：`unitId(string, 如 CH0221) / level(1起) / exp(等级内累积，升级结算在养成层) / breakStage(0=未突破，1~N 对应突破表行) / skillLevelNormal / skillLevelE / skillLevelQ(均1起) / unlockedNodes[]`。上限校验归养成层，仓库只做下限防御。

| API | 说明 |
|-----|------|
| `HasCharacter(unitId)` / `TryGetEntry(unitId, out entry)` / `Snapshot()` | 查询（写操作一律走管理器，直改不落盘） |
| `AddCharacter(unitId)` | 登记新角色（初始 1 级未突破），已拥有幂等拒绝 → 广播 `CharacterAcquired` |
| `SetLevel / AddExp / SetExp / SetBreakStage / SetSkillLevelNormal / SetSkillLevelE / SetSkillLevelQ / UnlockNode` | 养成写入，成功即广播 `CharacterDataUpdated`；UnlockNode 重复解锁幂等拒绝 |
| `SaveData() / LoadData()` | 手动持久化；LoadData 内 Normalize（同 unitId 留首个、字段下限防御、节点去重） |

## PlayerDataCenter（门面，static）

- `SaveAll()`（退游戏/切场景前兜底全量落盘）、`WipeAll()`（WipeFolder 删 `PlayerData/` 整目录 + 各域 LoadData 回默认，调试用不可恢复）
- **新账号默认数据（2026-09-28）**：`IsNewAccount()`（`PlayerData/` 目录不存在 = 从未落档）+ `EnsureNewAccountDefaults()`（新账号发默认角色 + 初始金币，老账号幂等跳过）。默认数据：`DefaultCharacterIds = {CH0221}`（随 CharacterTable 扩充追加）、初始金币 `CurrencyIds.Gold × 50000`（仅保证养成/商店链路可测，非数值定案）。接线：`Preloader.Start` 在 `MessageTool.Init()` 后、任何 UI 读档前调用一次
- ⚠️ **新账号判据污染**：OnEnable 之类提前落盘会让 `PlayerData/` 目录提前存在 → IsNewAccount 假阴性 → 默认角色不发。探针类脚本必须延迟发放（已踩，见 [[08-踩坑与排查/序列化与存档]]）
- 将来对接服务器时在此加上传打包入口
