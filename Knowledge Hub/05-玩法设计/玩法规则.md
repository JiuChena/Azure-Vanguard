# 玩法规则（游戏设计）

> 玩法规则与系统设计的单一参考。技术实现见 03/04 对应篇，路线图见 [[01-项目总览/系统路线图]]。
> 标注约定：✅ 已定稿（含拍板日期）· 📝 本次补全提案（待用户拍板）· 数值均为占位非定案。未拍板项汇总另见 [[05-玩法设计/设计挂账]]。

## 定位（2026-09-29 拍板）

- **题材**：二次元学园风。学生角色（学员）出战，玩家以指挥者身份带学员作战。主城入口 `students`（学员）/ `cultivated`（养成）命名即由此来。
- **平台**：**PC 优先**。键鼠输入、横屏 16:9、性能预算按 PC 算（UGUI + URP 现状不受影响，战斗内同屏单位数可放宽）。
- **商业化**：抽卡 + 商店 + 体力已按 F2P 口径规划（服务端方案含 ICP/版号路径）。买断 vs F2P 最终口径未拍板 📝，系统设计按 F2P 推进。

## 核心循环 📝（归纳自已落地系统，待确认）

```
日常循环：登录 → 领体力/任务 → 关卡战斗（清体力）→ 养成/商店/抽卡 → 下线
成长循环：关卡 → 材料+货币 → 养成（等级/突破/技能/节点）→ 战力提升 → 推进更难关卡
```

- 体力限制每日游玩时长（时间恢复）；付费/肝度换取加速。
- 养成是长期目标，关卡是 daily 玩法主体，抽卡是新角色入口。

## 战斗玩法（形态 ✅ 2026-09-29 拍板，数值/敌人 📝）

### 已定稿

- **形态**：RTS+塔防混合——**明日方舟式小区域塔防守卫**（守点、波次推进）为骨架。
- **同步**：客户端本地权威模拟 + 战报同步（指令流水 `{seq, type, cost, params}`，结算整包上传）。帧同步/服务器重模拟不做（已否决，方案见 [[04-模块/服务端与网络【骨架】]]）。
- **局内经济**：点数（波次奖励 + 时间供给，收入规则可算 = 服务器可推算任意时刻上限）。

### 玩家操作形态（2026-09-29 拍板，核心定义）

玩家**不直接操控角色本体**（无摇杆/方向键），而是在三个维度下达指令；每维度均可手动或交给自动模式：

| 维度 | 手动 | 自动 |
|------|------|------|
| **站位** | 点击场景中可抵达位置 → 该角色移动过去确定站位 | 按角色策略逻辑自判（例外见下） |
| **锁定目标** | 玩家手动选择锁定目标 | 默认索敌规则 |
| **技能释放** | **技能指示器**（范围/朝向/角度预览，参考碧蓝档案）择时择位释放 | 按角色策略逻辑判定时机 |

- **每角色独立自动开关**：八个角色逐个点技能不现实，每个角色有 auto toggle；开自动 = 站位/目标/技能时机全交策略逻辑。主力输出/辅助建议手动（玩家决定时机/位置/角度），次要角色开自动省操作。
- **角色平时不自主移动**（点选移动确定站位后站桩输出）；唯一例外：攻击/受击范围内出现**掩体**时可自主躲避。
- 关键角色技能 = 手动择时机/位置/角度（指示器）；这是操作深度的主体。

### 由此推出的战斗框架需求（⑤ 的实际范围）

| 子系统 | 说明 | 依赖 |
|--------|------|------|
| 点选寻路移动 | 点击可达位置 → NavMesh/格子寻路 | 场景导航数据 |
| 索敌/锁定系统 | 默认索敌规则 + 玩家手动锁定覆盖 | 敌人管理 |
| 技能指示器 | 范围/朝向/角度预览 UI（BA 式） | 技能表（SkillEffectTable.range 已有列） |
| 每角色策略配置 | 自动模式的判定规则（何时开大/何时换位） | 表或 SO，行为键（BehaviorKey 惯例） |
| 掩体系统 | 范围内掩体自主躲避（远期可后置） | 场景掩体标记 |
| 波次系统 | WaveTable（待建）：刷怪波次/点数供给/奖励 | 配置表系统 |
| 局内指令交易 | 已定稿：放置/移动/复活/买道具/升属性/buff/场内道具 → 流水 | 网络层（战报） |

### 定稿 ✅（2026-10-14 战斗动工拍板）

- **点位结构**：**连续空间 NavMesh**——点击任意可达点自由站位，场景烘 NavMesh，掩体=障碍物标记，技能指示器自由形状。
- **部署规则**：**点数部署（明日方舟式）**——上场本身花点数，与局内点数经济耦合；部署费用/点数速率数值 📐 届时给占位公式。
- **胜负条件**：**继承式可重写判定脚本**（策略基类 + 关卡引用具体实现）——普通关默认实现 = 守点血量归零败 / 清完全部波次胜；挑战关继承重写（如限时全歼 + 守点血量健康等多条件）。

### 仍待定 📝

- 敌人设计（类型/AI/数值）、点数速率、复活/道具定价、部署位上限/再部署冷却、每角色部署费用。

## 养成（数据形状 ✅ 落库，操作层 ✅ 服务侧）

### 五维成长（定稿，实现见 [[04-模块/角色养成系统]]）

| 维度 | 范围 | 消耗 | 校验归属 |
|------|------|------|---------|
| 等级 | 1~80（cap 由突破阶段定） | 经验道具 + 金币 📝 | 养成操作层 |
| 突破 | 5 阶段（levelCap 20→80） | BreakthroughTable.costItems（itemId:count） | 养成操作层 |
| 技能 | 普攻/E/Q 各 1~10 | 📝 提案：金币 + 技能材料 | 养成操作层 |
| 节点 | talent（行为键）+ bonus（属性%） | UnlockNodeTable.cost 或突破附带 | 养成操作层 |
| 星级 | starMult 乘区（将来） | 抽卡重复转换 📝 | 未开工 |

### 养成操作规则 ✅（2026-10-06 拍板，已落地）

- **升级结算**：`AddExp(unitId, exp)` → 仓库累积 → 循环结算（**本级所需经验 = 80 × level^1.5，浮点结算后向上取整**，幂曲线起手，常数单点写在业务逻辑可调）；到达 levelCap 后溢出经验**丢弃**（原神式，拍板确认），突破后继续吃。
- **突破**：前置 = 等级达当前 cap 且材料足；成功后 breakStage+1、连带免费解锁 `unlockNodeIds` 列出的节点。
- **节点解锁**：UnlockNodeTable.cost 材料校验（突破附带的节点免费，判定 = 是否出现在突破表）；talent 节点解锁的是行为键，bonus 节点解锁属性加成。
- **属性结算**：`CalculateStatsAsync(unitId, star=1)` 单一入口 = `floor(base × levelMult(level) × (1 + Σ同键百分比加成))`，战斗 v1 恒传 star=1。

## 经济（框架 ✅，产出/消耗闭环 📝）

- **货币是物品**（已定稿，见 [[04-模块/物品背包货币]]）：Gold=1 / StarlightStone=2，余额 = 背包计数；体力例外（玩家字段不走背包）。

| 产出 📝 | 消耗 📝 |
|---------|---------|
| 关卡首通（大额）+ 重复（小额） | 养成：经验/突破/技能/节点材料 |
| 任务奖励 | 抽卡：StarlightStone / 抽卡票 |
| 商店兑换 | 商店购买 |
| 抽卡重复转换 | 体力恢复加速（石头买体力，每日限次） |

## 抽卡 📝（规则全待定；随机必须服务端裁决 ✅）

- **卡池**：常驻池 + 限定 UP 池；池 = 配置表（PoolTable 待建）。
- **概率分层**：按 CharacterTable.rarity（列已有）。
- **保底**：硬保底 N 抽必出最高稀有度，计数落数据中心保底域（留位已备）；软保底可选后置。
- **重复**：转换为养成材料/碎片。
- **出货判定全在服务端**（已定稿），客户端只发请求收结果；保底计数以服务端为准。

## 任务 📝

- **类型提案**：主线 / 每日 / 每周 / 成就。
- **条件追踪**：事件驱动——EventCenter 广播（CharacterAcquired/CharacterDataUpdated/关卡通关等）→ 条件计数器；事件名已在 EventNames 逐步预留。
- **领奖**：条件达成手动领取 → 背包发奖；进度/领取状态落数据中心任务域（留位已备）。
- ⚠️ 动工前确认：通用框架速查表列有 `QuestManager`/`QuestConditionTracker`，但本项目 Core.Gear 下未见——先查明是复用还是按新域模板建（[[04-模块/任务系统【骨架】]]）。

## 体力 📝

- 提案：上限（随玩家等级/固定值）+ 时间恢复（如 1 点/6 分钟）+ 进关消耗；离线恢复至上限即止（不溢出）。
- 石头买体力每日限次（付费点）。
- 数据 = 当前值 + 上次恢复时间戳（数据中心留位已备）；**恢复结算归时间系统**，登录时一次性补算（时间戳差值），不逐秒 tick。

## 时间系统（③ 底座，未开工）

- 驱动对象：体力恢复 tick、商店每日刷新、任务每日/每周重置。
- 📝 提案：统一"游戏时间源"抽象（ITimeProvider 之类），本地实现起步（服务端接入前用本地时间），服务端时间接口留位；重置类结算用"上次结算时间戳 + 登录补算"模式，与体力同构。

## 商店 📝

- 货架 = ShopTable（待建）：商品 itemId、价格（货币+数量）、限购次数、刷新规则。
- 每日刷新戳 + 购买计数（数据中心留位已备）；购买走服务端裁决（已定稿）。

## 关卡 📝

- 结构提案：章节 → 关卡；stageId → 通关/星级（数据中心留位已备）。
- 星级条件提案：通关 / 限时 / 存活数——三星解锁扫荡（扣体力，发重复奖励）。
- 首通奖励（大额）与重复奖励（小额）区分，见经济闭环。
