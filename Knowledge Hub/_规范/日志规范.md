# 日志规范

开发日志记录**每个批次**的改动，服务于：回溯"这为什么这么改"、检索"哪天动过哪块"、接手 AI 理解演进史。

## 单条日志格式（固定字段）

```markdown
## [YYYY-MM-DD] 批次标题
- **改动模块**: 04-模块/xxx、03-框架/xxx（代码侧：Assets/Scripts/...）
- **改动内容**: 本批次实际做了什么（要点列表）
- **改动原因**: 修复 XX 问题（现象/根因一句话）｜主动优化（意识到的问题一句话）
- **验证**: 编译三重验证 / smoke X 断言 / Play 截图（路径）
- **关键词**: `词1` `词2` `词3`（3~6 个，供索引检索）
- **遗留**: 待用户项 / 挂账（无则省略此行）
```

字段要求：

- **改动模块**：知识库文档路径 + 代码侧路径都写；跨多模块逐一列出
- **改动原因**：必须区分两类来源——**事故修复**（哪里出了问题、现象是什么）与**主动预防/优化**（主动意识到什么问题）。这是日志最重要的字段，禁止省略或写"例行更新"
- **验证**：写了什么验证手段、结果如何；没有验证就写"未验证+原因"
- **关键词**：选"将来会按这个词搜"的词——类名、系统名、问题类型（如 `CultivatePanel` `池化` `竞态`）

## 分卷规则

- 单卷文件 ≤ **1000 行**；写完最后一条日志达到上限，即新开 `Log-YYYY-MM_卷N.md` 继续写
- 卷文件只追加不回改；写错了追加一条更正日志，不删旧条目
- 同日多批次 = 多条日志条目，不合并
- 卷命名：`Log-YYYY-MM_卷N.md`（按起始月份）

## 索引（强制）

**每写一条日志，必须同步在 `07-更新日志/日志索引.md` 追加一行**：

```
| 日期 | 标题 | 模块 | 关键词 | 链接 |
```

检索路径：先查索引按关键词定位 → 跳对应卷。归档日志（旧 journal）也已全部登记在索引中。

## 归档

`07-更新日志/归档/` 存放 2026-06-20 ~ 2026-10-10 的旧 journal（原样保留，不按新格式重写）。旧日志没有标准化的"关键词"行，索引中按其小节标题人工提炼关键词代替。
