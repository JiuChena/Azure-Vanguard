# 2026-09-10 玩法方向改版：RTS×TD 融合

> 下午的改版决定，优先级高于本日早间的职业体系调整记录（后者内容已被本次改版继承）。

## 改版决定（用户确认）

- 玩法定位由"明日方舟式塔防"改为**即时战略×塔防融合**：不再复刻明日方舟，旧版 git 历史可回溯。
- 敌人**固定路径**行进（下沉区内 NavMesh 寻路）；编队上限 **6 人**，战斗中不可追加；自动/手动模式**按角色独立切换**。
- 用户补充的关键设定：**敌人仅在下沉区移动**；地图分上下层，上层放输出/辅助角色，下层放重装角色，上下层不互通；下层敌人寻路用 NavMesh；"可以阻挡的东西都会设置一下"（阻挡由重装 + 掩体墙承担）。
- 场内点数统一经济：初次部署/阵亡复活/道具建造共用；复活可花点数立即或倒计时自动。
- 场内经验成长：杀敌/总治疗量/助攻 → 伤害提升；局内:局外成长 = **3:7**。
- 战前携带场内道具（种类上限 3）：掩体墙（多属性多价格）/ 防御塔 / 回血桩 / Buff 桩，战斗内用场内点数购买放置。

## 背包系统启动（下午，功能拆分轮）

- 功能拆分顺序决策：用户选择先做**背包系统**（背包/商店通用，先搭基层），战斗侧网格点位/BetterHSM 注册延后。
- 用户确认的设计决策：代码位置 `Assets/Scripts/CSharp/Core/Gameplay/Inventory/`（Gameplay 通用模块，命名空间 `Framework.Gameplay.Inventory`）；**货币视为特殊物品**（Kind=Currency，统一增删查接口，不设独立钱包）；本期只做无 UI 基层；物品条目只存 **ID + 数量**（无每实例状态，拓展靠功能扩展追加 Key）。
- 技术调研结论：BinaryDataManager 复用（[Key(int)] 只追加契约、无迁移机制需自备 Version 字段）；EventNames 已预留 `BagUpdated`/`StorePurchased` 常量；项目无通用配置表加载器（自建 ItemCatalogSO 聚合资产）；全项目无 asmdef、无业务层目录。
- 产出：`Assets/Technical Documentation/背包系统/背包系统.md`（初版设计稿，含 M1-M4 里程碑）+ `README.md` 索引（目录首次建立）；04-外围系统预留背包章节状态更新。
