## 2026-11-06: 战斗模块服务化（CombatService 全局单例 + 子服务）

- **背景**：`CombatManager`（1073 行场景 Mono）四合一，`BattleController` 又独立持有模拟状态，职责边界模糊；用户要求合并为全局单例并拆子服务，且进入/离开战斗场景都要 `Reset` 保证数据干净。
- **决策**：
  1. `CombatService` 为纯 C# 全局单例（非 MonoBehaviour），常驻；场景只保留 `CombatSceneEntry` 承载 LevelConfig/出怪点/路线/守点/viewRoot/部署区等序列化引用。
  2. 子服务拆分：`CombatRosterService`（单位档案）、`CombatWaveService`（波次）、`CombatResourceService`（点数/CD/能量）、`CombatEffectService`（角色/敌人分区全局 Effect + 光环）、`CombatOutcomeService`（守点/胜负/快照）、`CombatCommandService`（指令流水）、`CombatAssemblyService`（装配工厂）、`CombatViewService`（视图桥）、`CombatDeployService`（拖放）、`CombatSelectionService`、`CombatEventService`。每份状态单一写者；`CombatService` 只做门面与 Step 编排。
  3. `Reset()` 在进入/离开场景双调用，另加 `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` 兜底 Domain Reload 关闭；`BattleSessionId` 防旧场景迟到拆除误伤新战斗；`CreateForSimulation` 返回 detached 实例隔离验证脚本。
  4. `CombatSceneEntry` 沿用原 `CombatManager.cs` 的 `.meta` GUID 与全部字段名，`CombatTest.unity` 组件零手工重连（已回读序列化字段全非空）。
- **影响**：删除 `BattleController` / `CombatManager` / `TalentEffectContainer` / `TalentAura` / `EnergyManager`；9 个 AgentScripts 迁移后全绿（SIM 54、DECISION 40、TALENT 27、AIM 27、FACING 23、SKILL-EFFECT 13、SKILL-ENERGY 23、TARGETING 9、ENTRY 14）；详见 [[04-模块/战斗框架]] 服务化章节。
