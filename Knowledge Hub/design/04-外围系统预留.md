# 外围系统预留

> 本文档为第二版玩法设计稿（2026-09-10 RTS×TD 融合改版同步更新），描述目标设计而非当前代码现状。**原型不实现以下任何系统**，本文档只做框架级占位，防止后续设计越界。

## 总原则

- 每个系统标注"原型是否包含：否"，只定义目的、与核心循环的关系、接口方向与边界。
- **持久化边界**：框架现状仅有本地持久化（BinaryDataManager，MessagePack 本地文件，见 `Knowledge Hub/modules/Gear 基础模块.md`）；正式版的账号/服务器持久化不在框架现状内。占位设计不得假设服务器能力，涉及账号数据的系统须注明"正式版需服务器，框架现状仅本地"。

## 背包系统（基层建设已启动）

- **原型是否包含：否**（但数据/服务基层作为 Gameplay 通用模块先行建设，2026-09-10 用户决定）
- 目的：养成材料、道具、货币的持有与管理。
- 与核心循环关系：承载 [[02-干员与养成]] 的升级材料与 [[03-关卡与敌人]] 的结算产出；场内道具库（掩体墙/桩塔）若引入"道具持有/购买入库"玩法，也挂接在背包上。
- 关键决定：物品条目只存 **ID + 数量**，其他语义在配置；**货币视为特殊物品**（Kind = Currency）走统一接口，不设独立钱包；背包 UI 本期不做。
- 技术设计：见 `Assets/Technical Documentation/背包系统/背包系统.md`（模块拆分、API 契约、里程碑）。
- 边界：物品分类页签、整理、过期、装备类物品全部后置。框架现状仅本地持久化。

## 商店系统（基层设计已出）

- **原型是否包含：否**（但基层设计已完成，随背包基层建设节奏实现，2026-09-10）
- 目的：资源与道具的获取渠道之一，长线货币回收口。
- 与核心循环关系：消耗货币兑换养成材料、场内道具、抽卡券等；货币即物品，扣款发货全走背包服务层接口。
- 关键决定：商品编排走配置表管线（Excel 商品表 → shop_config.json）；复用已预留的 `StorePurchased` 事件；限购记录独立存档；商店不直接发放干员（干员只走抽卡）。
- 技术设计：见 `Assets/Technical Documentation/商店系统/商店系统.md`、`Assets/Technical Documentation/配置表管线/配置表管线.md`。
- 边界：商业化付费、礼包、充值回返均后置；每日/每周刷新周期后置。

## 抽卡系统（占位）

- **原型是否包含：否**
- 目的：干员获取的长线驱动。
- 与核心循环关系：解锁干员 → 进入编队池（替换 [[02-干员与养成]] 的"默认解锁"）。
- 接口方向：干员解锁数据结构（干员 ID → 解锁标记），干员数据结构无需改动。
- 边界：概率、保底、货币消耗、卡池轮换均不在本版范围。正式版需账号/服务器持久化，框架现状仅本地。

## 基建系统（占位）

- **原型是否包含：否**
- 目的：离线产出与养成加速（制造/贸易类设施结构）。
- 与核心循环关系：产出养成资源，反哺 [[02-干员与养成]] 成长线。
- 接口方向：设施等级表 + 周期产出结算（可由 Gear Timer 与本地存档承载）。
- 边界：设施布局、交互、数值全部后置。

## 剧情与世界观（占位）

- **原型是否包含：否**
- 题材方向【微创新-题材】：近未来海洋——"大潮汐"灾变后人类退守海上城市群，玩家指挥"先锋舰队"在风暴海域开辟航道；敌人"潮兽"自深渊而来。干员与敌人代号已按此题材命名（见 [[02-干员与养成]]、[[03-关卡与敌人]]）。
- 接口方向：关卡前置/后置短文本 + 干员档案页占位。
- 边界：不做剧情演出系统、不做语音、不做分支叙事。

## 活动系统（占位）

- **原型是否包含：否**
- 目的：限时关卡与奖励投放。
- 接口方向：关卡表 + 时间窗配置。
- 边界：全部后置。

## 经济系统（占位）

- **原型是否包含：否**
- 货币占位命名（海洋题材，正式数值后置）：
  - **航海币**：通用金币，养成消耗。
  - **潮汐石**：高级货币，抽卡消耗。
  - **理智**：体力，进入关卡消耗（见 [[00-策划案总览]] 术语表）。
- 边界：获取/消耗数值、商业化设计全部后置；原型中金币与经验材料固定发放（见 [[03-关卡与敌人]] 结算）。
