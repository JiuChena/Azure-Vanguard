# 原型技术映射

> 本文档为**第二版**玩法设计稿（2026-09-10 RTS×TD 融合改版），描述目标设计而非当前代码现状。只写设计概念与框架能力的对应关系、现状缺口与风险，**不写实现方案**，不替框架做设计决定。

## 映射总表

状态定义：**现状可用**（框架已有，直接使用）/ **需扩展**（框架有挂点，按文档化路径扩展）/ **需新增**（框架无此能力，业务实现）。

| 设计概念 | 框架能力 | 状态 | 说明 |
| --- | --- | --- | --- |
| 网格点位系统（部署位/建造位/路径参照） | 无（Tilemap 包已安装，但无战斗网格模块） | **需新增** | 业务 GridManager：格子数据、上层位/下层位/建造位标记、攻击范围计算；Tilemap/ProGrids 仅作编辑期辅助候选 |
| 上下层战场与高度差 | 无 | **需新增** | 上层/下沉区两个逻辑层 + 表现层地形；层级归属作为干员/敌人的基础数据 |
| 干员/敌人实体能力组合 | GAS `GameplayAbilitySystem` | 现状可用 | 实体挂 GAS，Ability 列表按序驱动（`架构总览.md:86-98`） |
| 敌人行为状态机 | BetterHSM | **需新增** | 正式注册方案与工厂均未建（`GAS 与 BetterHSM.md:192-194`）；无工厂前不得挂 `BetterHSMAbilitySO`（初始化会抛配置错误）；需新增 Enemy 分类注册 ID 与工厂 |
| **干员自动战斗 AI（职业选位策略）** | BetterHSM + 纯 C# 决策模块 | **需新增** | 本版最大新增项：按职业权重对候选点位评分选位、点位间移动、模式切换仲裁；决策为纯 C#，移动/交战状态走 BetterHSM |
| 干员/敌人移动 | NavMeshAgent（Unity 内置） | **需新增** | 引擎 NavMesh 现成，但下沉区 NavMesh 烘焙、路径编排（波次参照路径）与移动业务封装均需新建 |
| 干员技能 | GAS 业务 AbilitySO 三件套 | 现状可用 | 每技能一个 AbilitySO（`templates/新建 Ability 模板`） |
| 场内经验成长 | GAS Attribute（经验/场内等级/伤害加成） | **需扩展** | 经验来源（击杀/治疗/助攻）需事件统计管道；成长公式为纯数值，难度低 |
| 场内点数经济 | 无 | **需新增** | 全局点数池：自然回复、部署/复活/建造扣费；纯逻辑模块，难度低 |
| 道具建造系统（掩体墙/防御塔/桩） | ObjectsPool + SO 配置 | **需扩展** | 建筑实体走对象池与 SO 配置；掩体墙阻挡逻辑、桩塔光环/索敌、耐久摧毁需新建 |
| 攻击/技能表现 | BehaviorEditor（动画/Hitbox/事件三轨道） | 现状可用 | `运行流程.md:131-151`；技能特效走 VFXPool |
| 战斗 UI（HUD/干员栏/道具栏/信息条） | PanelManager / PanelBase | 现状可用 | 面板加载与层级现成（`Gear 基础模块.md:121-141`）；干员模式徽标与复活倒计时为业务 UI |
| 部署/建造/选位交互输入 | Input System + InputButton | **需扩展** | `InputButton` 现仅 None/Jump/Sprint（`GAS 与 BetterHSM.md:149-157`）；点选交互建议走 uGUI 指针事件 + 相机射线（不占 InputButton），倍速/暂停等按钮按文档化路径扩展 InputButton 枚举 |
| 战斗镜头（固定俯视/平移/缩放） | Cinemachine（包已安装） | **需扩展** | 框架无镜头模块；用 Cinemachine 配置固定俯视角，平移缩放由业务层封装 |
| 数值配置 | ScriptableObject + BinaryDataManager | 现状可用 | 干员/敌人/关卡/道具静态配置走 SO；玩家进度（编队/等级/解锁）走 BinaryDataManager 本地存档（仅本地，无服务器） |
| 资源加载与回收 | Addressables Lease/Scope + ObjectsPool | 现状可用 | 波次敌人生成与道具建筑走对象池（`Gear 基础模块.md:60-73`） |
| 音频 | AudioManager | 现状可用 | Clip 加载由业务层 Scope 管理（`Gear 基础模块.md:83-96`） |
| 关卡流程与结算 | LoadSceneManager + EventCenter | 现状可用 | 场景加载统一走 LoadSceneManager；结算广播走 EventCenter |

## 原型范围清单

**做**：核心战斗循环（点数经济/部署/自动与手动模式/职业 AI 选位/复活/场内经验 3:7/道具建造/倍速暂停）、14 名干员、7 类敌人模板、4 类场内道具、3 个完整关 + 2 个概要关、本地存档（编队/等级/解锁）、测试满级开关、战斗 HUD 与部署建造交互。

**不做**：抽卡/基建/剧情/活动/经济（见 [[04-外围系统预留]]）、联网/服务器、精英化/潜能/专精、三星评价、剧情演出、飞行单位、学习型 AI。

## 技术风险清单

| # | 风险 | 影响 | 缓解方向 |
| --- | --- | --- | --- |
| 1 | **干员自动战斗 AI 选位**（职业策略评分、点位动态重选、与手动指令仲裁）从零建 | 核心玩法成立与否 | 先做规则化打分（候选点位 × 职业权重），3 个职业先行（重装/穿透/后援）跑通循环，再铺其余职业 |
| 2 | BetterHSM 正式注册方案从零建（首个实体状态图） | 敌人与干员 AI 起步成本 | 先做敌人"行军-交战-死亡"三态最小状态图 |
| 3 | 战斗网格点位系统全新建（部署位/建造位/路径参照三层语义） | 部署/建造/范围/AI 选位都依赖它 | 先做数据层（格子 + 三类点位标记 + NavMesh 面），表现后接 |
| 4 | NavMesh 路径编排与波次"路径进度"参照的结合 | 索敌优先级与漏怪判定 | 预定义路径作为逻辑参照序列，NavMesh 只负责行走，两者解耦 |
| 5 | 部署/建造/选位交互移动端手感 | 核心体验 | 先做"点选-确认"两步流，拖拽作为增强迭代 |
| 6 | 3D 卡通角色资产量（14 干员 × 待机/移动/攻击/技能） | 表现完成度 | 原型用占位模型 + BehaviorEditor 最小动画集（较旧版新增移动动画） |
| 7 | 潮汐水位机关涉及下层位/建造位动态变化 | 网格系统复杂度 | 放 Boss 关最后实现，可降级为静态机关 |

## 开放问题清单

1. AI 决策的运行层级：纯 C# 每帧评分 vs 低频 tick 评分（性能与响应性平衡）——需技术预研后拍板。
2. NavMesh 与网格点位的坐标映射规范（部署位/建造位吸附到 NavMesh 面的方式）。
3. 暂停时下达指令的实现层级（指令队列 vs 逻辑时钟冻结）——与倍速实现层级（全局 TimeScale vs 独立逻辑时钟）一并预研。
4. 敌人是否主动攻击桩塔/掩体墙（当前设计：不主动）——影响敌人索敌实现复杂度。
5. 本地存档版本化策略（BinaryDataManager 的 MessagePack Key 稳定性约定）。
