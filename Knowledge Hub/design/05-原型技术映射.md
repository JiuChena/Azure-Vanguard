# 原型技术映射

> 本文档为第一版玩法设计稿，描述目标设计而非当前代码现状。只写设计概念与框架能力的对应关系、现状缺口与风险，**不写实现方案**，不替框架做设计决定。

## 映射总表

状态定义：**现状可用**（框架已有，直接使用）/ **需扩展**（框架有挂点，按文档化路径扩展）/ **需新增**（框架无此能力，业务实现）。

| 设计概念 | 框架能力 | 状态 | 说明 |
| --- | --- | --- | --- |
| 格子地图与部署位 | 无（Tilemap 包已安装，但无战斗网格模块） | **需新增** | 业务 GridManager：格子数据、部署位标记、攻击范围计算；Tilemap/ProGrids 仅作编辑期辅助候选 |
| 敌人/干员实体能力组合 | GAS `GameplayAbilitySystem` | 现状可用 | 实体挂 GAS，Ability 列表按序驱动（`架构总览.md:86-98`） |
| 敌人行为状态机 | BetterHSM | **需新增** | 正式注册方案与工厂均未建（`GAS 与 BetterHSM.md:192-194`）；无工厂前不得挂 `BetterHSMAbilitySO`（初始化会抛配置错误）；需新增 Enemy 分类注册 ID 与工厂 |
| 干员技能 | GAS 业务 AbilitySO 三件套 | 现状可用 | 每技能一个 AbilitySO（`templates/新建 Ability 模板`） |
| 攻击/技能表现 | BehaviorEditor（动画/Hitbox/事件三轨道） | 现状可用 | `运行流程.md:131-151`；技能特效走 VFXPool |
| 战斗 UI（HUD/卡片栏/信息条） | PanelManager / PanelBase | 现状可用 | 面板加载与层级现成（`Gear 基础模块.md:121-141`） |
| 部署交互输入（点选/拖拽/朝向轮盘） | Input System + InputButton | **需扩展** | `InputButton` 现仅 None/Jump/Sprint（`GAS 与 BetterHSM.md:149-157`）；部署主交互建议走 uGUI 指针事件 + 相机射线（不占 InputButton），倍速/暂停等按钮按文档化路径扩展 InputButton 枚举 |
| 战斗镜头（固定俯视/平移/缩放） | Cinemachine（包已安装） | **需扩展** | 框架无镜头模块；用 Cinemachine 配置固定俯视角，平移缩放由业务层封装 |
| 敌人寻路 | 无 | **需新增** | 首版用关卡预定义路径点（waypoint 序列，见 [[03-关卡与敌人]] 地图规格），无需 NavMesh |
| 数值配置 | ScriptableObject + BinaryDataManager | 现状可用 | 干员/敌人/关卡静态配置走 SO；玩家进度（编队/等级/解锁）走 BinaryDataManager 本地存档（仅本地，无服务器） |
| 资源加载与回收 | Addressables Lease/Scope + ObjectsPool | 现状可用 | 波次敌人生成走对象池（`Gear 基础模块.md:60-73`） |
| 音频 | AudioManager | 现状可用 | Clip 加载由业务层 Scope 管理（`Gear 基础模块.md:83-96`） |
| 关卡流程与结算 | LoadSceneManager + EventCenter | 现状可用 | 场景加载统一走 LoadSceneManager；结算广播走 EventCenter |

## 原型范围清单

**做**：核心战斗循环（部署/阻挡/DP/技能/再部署/倍速暂停）、14 名干员、7 类敌人模板、3 个完整关 + 2 个概要关、本地存档（编队/等级/解锁）、测试满级开关、战斗 HUD 与部署交互。

**不做**：抽卡/基建/剧情/活动/经济（见 [[04-外围系统预留]]）、联网/服务器、精英化/潜能/专精、三星评价、剧情演出、飞行单位。

## 技术风险清单

| # | 风险 | 影响 | 缓解方向 |
| --- | --- | --- | --- |
| 1 | BetterHSM 正式注册方案从零建（首个实体状态图） | 敌人 AI 起步成本 | 先做"行军-交战-死亡"三态最小状态图 |
| 2 | 战斗网格系统全新建 | 部署/范围/路径三大系统都依赖它 | 先做数据层（格子+部署位+路径点），表现后接 |
| 3 | 部署交互（拖拽+朝向轮盘）移动端手感 | 核心体验 | 先做"点选-确认"两步流，拖拽作为增强迭代 |
| 4 | 3D 卡通角色资产量（14 干员 × 待机/攻击/技能） | 表现完成度 | 原型用占位模型 + BehaviorEditor 最小动画集 |
| 5 | 潮汐水位机关涉及部署位动态变化 | 网格系统复杂度 | 放 Boss 关最后实现，可降级为静态机关 |

## 开放问题清单

1. 网格编辑器形态：Tilemap 扩展 vs 自定义 Inspector 绘制——需技术预研后拍板。
2. 敌人"攻击高台位"是否进入原型（当前设计：不进入，Boss 范围技能除外）。
3. 倍速实现层级：全局 TimeScale vs 独立逻辑时钟（影响与 Gear Timer 的兼容性）。
4. 本地存档版本化策略（BinaryDataManager 的 MessagePack Key 稳定性约定）。
