# 商店系统技术文档

> 状态：**设计稿（待实现）**——描述商店系统目标设计。创建于 2026-09-10。依赖背包系统（见 `Assets/Technical Documentation/背包系统/背包系统.md`）。

## 概述

商店是资源与道具的获取渠道，货币回收口。**商店不直接发放干员**（干员获取只走抽卡）；货币即物品（Kind=Currency），商店扣款与发货全部通过背包服务层接口完成。

设计要点（2026-09-10 确认）：

- 商品编排走**配置表管线**（Excel `商品表` → `shop_config.json` → ShopCatalog），策划可自行维护。
- 复用已预留的 `EventNames.StorePurchased` 事件常量。
- 本期范围：无 UI 基层；商店面板随背包 UI 一起后置。

```text

                                        │ TextAsset（Addressables）
```

## API 参考

### ShopGoodsConfig（JSON 配置类）

```csharp
[Serializable]
public sealed class ShopGoodsConfig
{
    public int goodsId;            // 主键，0 保留
    public int itemId;             // 发货物品 ID（对应 item_config）
    public int count;              // 单次购买发货数量
    public int currencyItemId;     // 价格货币的物品 ID（航海币/潮汐石）
    public long price;             // 单价
    public int purchaseLimit;      // 限购次数；0 = 不限
    public int sort;               // 排序权重，小在前
    public bool onShelf;           // 上架标记
}
```

### ShopCatalog

| API | 说明 |
| --- | --- |
| `bool TryGet(int goodsId, out ShopGoodsConfig goods)` | O(1) 索引 |
| `IReadOnlyList<ShopGoodsConfig> GetOnShelfGoods()` | 上架商品按 sort 升序 |

### ShopManager（单例）

| API | 签名 | 说明 |
| --- | --- | --- |
| 购买 | `bool Buy(int goodsId)` | 完整购买流程（见下），成功返回 true |
| 已购次数 | `int GetPurchasedCount(int goodsId)` | 限购展示用 |
| 可否购买 | `bool CanBuy(int goodsId, out string failReason)` | 上架/限购/余额三重校验 |
| 保存 | `void Save()` | 限购记录落盘 |

**Buy 流程（顺序固定）**：

```text
1. TryGet(goodsId) 失败 → LogError（配置错误），返回 false
2. onShelf == false → 返回 false
3. purchaseLimit > 0 且已购次数 ≥ limit → 返回 false（限购）
4. InventoryManager.HasEnough(currencyItemId, price) → 不足返回 false
5. InventoryManager.TryRemove(currencyItemId, price)          ← 原子扣款
6. InventoryManager.AddItem(itemId, count)                    ← 发货
   （步骤 5 成功后 6 理论上必成功；若失败属严重错误，回滚扣款并 LogError）
7. 已购次数 +1，保存限购记录
8. EventCenter.SetEventTrigger(EventNames.StorePurchased)
```

### PurchaseRecordData（存档契约）

```csharp
[MessagePackObject]
public sealed class PurchaseRecordData
{
    [Key(0)] public int Version = 1;
    [Key(1)] public List<PurchaseEntry> Entries = new();   // goodsId → 已购次数
}

[MessagePackObject]
public sealed class PurchaseEntry
{
    [Key(0)] public int GoodsId;
    [Key(1)] public long Count;
}
```

持久化：路径 `"PlayerData/Shop/"`，文件名 `"PurchaseRecord"`；购买成功即保存。遵循 Key 只追加契约。刷新周期（每日/每周重置）为外围占位，原型不实现——`purchaseLimit` 为累计限购。


## 注意事项

1. **商店只消费背包接口**：不直接读写物品数据、不感知分堆；扣款与发货顺序不可颠倒。
2. **发货失败必须回滚**：AddItem 失败（如物品配置缺失）时退还已扣货币并 LogError——这是唯一允许商店触碰扣款补偿的场景。
3. **限购按 goodsId 记账**：商品下架不改历史记录；复用 goodsId 上新商品视为配置错误（导出脚本不校验跨版本，需策划约定）。
4. **商店不发放干员**：干员解锁只走抽卡接口（04-外围系统预留），商店商品表不允许出现干员类商品。
5. **刷新周期后置**：每日/每周商店重置为外围占位，当前 purchaseLimit 为累计限购；未来加重置时在 PurchaseRecordData 末尾追加周期字段，不改既有 Key。
6. **事件成对注册**：同背包（Gear 使用检查第 3 条）。
