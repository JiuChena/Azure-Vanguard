# 背包系统技术文档

> 状态：**基层已实现（2026-09-10）**——数据层（ItemStack/InventoryData）与服务层核心（InventoryManager：增删查 + 即改即存 + BagUpdated 事件）已落地，编译验证以 Unity Console 为准。定义层（ItemConfig/ItemCatalog）与 CanAdd/GetByKind/ItemIds 待 C0 配置管线就绪后接入；实现与设计的偏差：①字段命名采用项目惯例 camelCase（MessagePack [Key(int)] 契约不变）；②InventoryManager 为纯 C# 懒加载单例（与 AudioDataManager 同模式），无 OnDestroy 兜底，持久化依赖"变更即保存"；③存档加载时防御性合并同 ID 重复条目并剔除脏数据。

## 概述

背包系统是经济与养成类系统的数据基座：持有物品数量、提供统一的物品增删查接口、广播变更事件、本地持久化。商店、抽卡、结算发奖、场内道具携带等系统都只依赖本系统的接口，不直接操作物品数据。

设计要点（2026-09-10 用户确认）：

- 物品条目只存 **物品 ID + 数量**（本项目无耐久/强化类每实例状态）；名称、图标、堆叠上限等静态语义在配置表（`item_config.json`）中，需要新语义时按功能拓展追加。
- **货币视为特殊物品**：航海币/潮汐石等货币是 `Kind = Currency` 的普通物品条目，走同一套增删查接口，不设独立钱包。
- 本期范围：**无 UI 基层**（定义层 + 数据层 + 服务层）；背包面板后置到商店/抽卡需要时再做。

## 架构模式

### 代码位置与命名空间

```text
Assets/Scripts/CSharp/Core/Gameplay/Inventory/
├── ItemKind.cs                # 物品大类枚举
├── ItemConfig.cs              # 物品静态配置类（item_config.json 反序列化目标）
├── ItemCatalog.cs             # 物品目录（加载 + ID 索引）
├── ItemStack.cs               # 存档条目（MessagePack）
├── InventoryData.cs           # 存档根对象（MessagePack）
└── InventoryManager.cs        # 服务层单例（增删查 + 事件 + 持久化）
```

命名空间沿用 Gameplay 框架惯例：`Framework.Gameplay.Inventory`。属于 Gameplay 通用模块（用户指定），不放 Gear（Gear 不承载游戏语义），不放业务层。

### 分层

```text
ConfigTables/物品表.xlsx ──导出── Assets/Settings/Config/item_config.json
                                        │ TextAsset（Addressables）
定义层          ItemConfig ◄──────── ItemCatalog（只读 ID 索引）
                    │
服务层          InventoryManager（唯一读写入口，唯一存档者）
                    │                    │ 持久化
表现层（后置）  背包面板 ──订阅── BagUpdated    BinaryDataManager
```

依赖方向单向向下；任何系统不得绕过 `InventoryManager` 直接改 `InventoryData`。

## API 参考

### ItemKind（枚举）

| 值 | 含义 |
| --- | --- |
| `Currency` | 货币（航海币、潮汐石、抽卡券等） |
| `Material` | 养成材料（金币、经验材料等结算产出） |
| `BattleItem` | 场内道具（掩体墙、防御塔、功能桩的"持有"载体，若未来引入道具入库玩法） |
| `Consumable` | 消耗品（体力药剂等，外围占位） |
| `Misc` | 杂项 |

配置表 `kind` 列为字符串（`currency/material/battle_item/consumable/misc`），加载时映射为枚举。

### ItemConfig（JSON 配置类）

```csharp
[Serializable]
public sealed class ItemConfig
{
    public int itemId;              // 全局唯一，0 保留不使用
    public string name;             // 显示名
    public string kind;             // ItemKind 字符串，加载时映射
    public long stackLimit;         // 单组堆叠上限；0 = 不限（货币用 0）
    public string iconKey;          // 图标 Addressables key（无 UI 阶段可空）
    public string description;      // 描述
    public string source;           // 来源说明（获取途径文案）
}
```

### ItemCatalog

```csharp
public sealed class ItemCatalog
{
    public bool TryGet(int itemId, out ItemConfig config);      // O(1) 字典索引
    public IReadOnlyDictionary<int, ItemConfig> Index { get; }
    public static ItemCatalog LoadFrom(TextAsset json);          // 初始化期调用一次
}
```

### ItemStack / InventoryData（存档契约）

```csharp
[MessagePackObject]
public sealed class ItemStack
{
    [Key(0)] public int ItemId;
    [Key(1)] public long Count;
}

[MessagePackObject]
public sealed class InventoryData
{
    [Key(0)] public int Version = 1;             // 存档版本，迁移抓手
    [Key(1)] public List<ItemStack> Items = new();
}
```

Key 契约遵循 BinaryDataManager 约定：整数索引、**只追加不重排不删除**；框架无迁移机制，Version 字段为未来自建迁移预留。

### InventoryManager（单例）

| API | 签名 | 说明 |
| --- | --- | --- |
| 取数量 | `long GetCount(int itemId)` | 未拥有返回 0 |
| 是否足够 | `bool HasEnough(int itemId, long amount)` | 商店/养成消耗前置校验 |
| 可否增加 | `bool CanAdd(int itemId, long count)` | 含堆叠上限裁决；未知 ID 返回 false |
| 增加 | `bool AddItem(int itemId, long count)` | 自动分堆（按 StackLimit 拆多条目），失败返回 false 且无副作用 |
| 扣除 | `bool TryRemove(int itemId, long count)` | 数量不足整体失败（原子操作，不部分扣除） |
| 按类查询 | `IReadOnlyList<ItemStack> GetByKind(ItemKind kind)` | UI/商店用；货币过滤 `Kind == Currency` |
| 全量快照 | `IReadOnlyList<ItemStack> Snapshot()` | 只读视图，禁止外部修改 |
| 保存 | `void Save()` | 写 `BinaryDataManager` |

事件：每次成功增删后触发 `EventCenter.Instance.SetEventTrigger(EventNames.BagUpdated)`（复用已预留的零参事件常量；现有 UI 少，直接全量重读，不做差量推送）。

持久化：路径 `"PlayerData/Inventory/"`，文件名 `"Bag"`；**每次变更即保存**（数据量极小，沿用 AudioDataManager 的"改即存"先例）；`OnDestroy` 兜底保存一次。

## 使用流程

```csharp
// 商店扣款（货币即物品）
if (InventoryManager.Instance.HasEnough(ItemIds.TidalStone, price))
{
    InventoryManager.Instance.TryRemove(ItemIds.TidalStone, price);
    InventoryManager.Instance.AddItem(ItemIds.ItemIdOfGoods, 1);
}

// 结算发奖
InventoryManager.Instance.AddItem(ItemIds.VoyageCoin, 500);

// UI 订阅刷新
EventCenter.Instance.Register(EventNames.BagUpdated, RefreshBagPanel);
// OnHidePanel 时 Unregister（成对注册）
```

物品 ID 引用统一走常量类 `ItemIds`（`const int`，与配置表主键对齐），禁止散落魔法数字。

## 功能拆分与里程碑

| 里程碑 | 内容 | 交付物 |
| --- | --- | --- |
| C0 管线 | `Tools/ConfigExporter/export_config.py` + 物品表.xlsx 样例 | item_config.json 可导出（见配置表管线文档） |
| M1 定义层 | `ItemKind`、`ItemConfig`、`ItemCatalog`、`ItemIds` 常量类；示例物品（航海币/潮汐石/金币/经验材料） | 配置可加载，目录可索引 |
| M2 数据层 | `ItemStack`、`InventoryData`、存档读写契约（Version 1） | 存档往返正确（存→读→字段一致） |
| M3 服务层 | `InventoryManager`：增删查、分堆与上限裁决、原子扣除、`BagUpdated` 事件、即改即存 | 接口完整可调用 |
| M4 验证 | 调试入口（测试菜单加/扣物品）；边界用例自测：超上限、扣超过持有、未知 ID、并发事件 | 验收清单通过 |

商店、抽卡在后续轮次接入，只消费 M3 接口，不需要改动背包内部。

## 注意事项

1. **Key 只追加**：`ItemStack`/`InventoryData` 的 `[Key(n)]` 字段禁止重排、删除、复用索引；新字段追加到末尾。
2. **堆叠上限裁决在服务层**：`AddItem` 内部按 `StackLimit` 分堆；调用方永远只表达"加 N 个"，不感知分堆。
3. **原子性**：`TryRemove` 数量不足时整体失败，不部分扣除；商店扣款因此可用"先 TryRemove 成功再 AddItem 发货"的顺序。
4. **未知物品 ID 是配置错误**：`AddItem` 对未在 item_config 注册的 ID 返回 false 并 `Debug.LogError`，不静默吞掉。
5. **货币即物品的约束**：货币条目由代码路径增删（商店/结算），不做丢弃/出售；如未来需要"背包内手动使用货币"，在配置层加开关而不是放宽服务层。
6. **事件成对注册**：订阅 `BagUpdated` 的面板必须在关闭时 `Unregister`（Gear 使用检查第 3 条）。
7. **零框架改动**：本模块只读使用 Gear 能力，不改 Gear/GAS 任何代码（05-原型技术映射 的零框架改动约束）。
8. **静态语义全部来自配置表**：改名/改描述/改上限一律改 Excel 重新导出，代码与 Unity 内不留第二份物品文本。
